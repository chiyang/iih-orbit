# 多個 Drive 檔案來源與授權續接

[文件索引](README.md) · [Google 連線設定](google-setup.md) · [任務資訊連結](task-document-phase1.md)

2026-10-15：完成本輪第一階段的多來源與前端授權續接。檔案來源設定保存在目前瀏覽器；Google 原檔與任務關聯各自保留，遠端同步備份繼續使用自己的連線。

## 新增與管理來源

1. 到「設定 → Google Drive」，按「新增檔案來源」。
2. 填寫來源名稱與 Google OAuth Client ID。可沿用主要 Client ID，也可使用另一個允許目前網站來源的 Client ID；Client ID 不等於 Google 帳號。
3. 保存後按該來源的「連線」，由 Google 選擇帳號並取得檔案名稱／資料夾資訊的唯讀權限。
4. 每個來源可以編輯名稱、重新授權、明確切換帳號、解除連線或確認移除。目前最多可新增 20 個額外來源。

「主要來源」直接沿用既有檔案瀏覽帳號及憑證，也能由主要 Google 連線的「一次授權全部服務」連線；它的 Client ID 在 Google 連線設定修改。額外來源使用自己的授權入口，包含相同 Client ID 的不同帳號，或相同帳號的不同 Client ID。

移除來源先顯示範圍及取消入口，只移除目前瀏覽器的來源設定與連線。已有任務資訊連結及 Google 原檔保留；來源名稱或 Client ID 改變也不改既有文件身份。

## 側欄與選檔

檔案側欄與任務選檔視窗上方均有精簡的來源選單與連線狀態。兩個畫面各自記住每個來源的目錄、搜尋及本次開啟期間的列表快取；側欄切換來源不會改變已開啟的選檔位置。切回來源時沿用尚有效的五分鐘快取。

選檔可以跨來源選取項目；單純切換來源保留已選內容。帳號、Client ID、資料世代或來源移除造成原選取背景變更時，捨棄尚未確認的新選取並提示重新選擇，原任務草稿保留。取消選檔不取消任務編輯。

同一 Drive 檔案在不同來源可見時，仍按原 Drive 檔案 ID 辨識，不因帳號或 Client ID 產生另一份來源。各來源的路徑、列表與授權結果分開；來源切換後，晚到的舊請求不寫回新列表。

第三階段新增跨畫面共用的檔案資訊查驗：列表、任務連結與選檔共用同一來源的名稱／位置與存取狀態，導航與搜尋仍各自獨立。任務可指定查驗來源；某來源失敗時保留另一來源的成功結果。設定另提供過期／全部檔案快取清理，保留連線與任務內容。[完整操作與快取規則](document-information-refresh.md)。

第四階段可從任務使用指定來源建立 Google 文件、試算表與簡報。建立使用獨立的 `drive.file` 授權，原帳號驗證與本機來源設定保留，不改瀏覽／備份憑證；只在本次頁面保存建立憑證。根位置及應用程式已獲准存取且可建立的資料夾可用，位置按來源隔離保存。設定提供建立結果接續與完全無引用來源整理。[建立文件與安全整理](document-creation-and-cleanup.md)。

側欄與選檔的路徑起點，主要來源顯示「Google Drive」，額外來源顯示自訂來源名稱；「與我共用」仍保留位置標示。任務資訊連結的名稱後提供相同的 ↗ 外開圖示，名稱與圖示共同開啟原項目。新加入的連結保存加入時的來源名稱及路徑快照，例如「研究文件 / 我的雲端硬碟 / 計畫資料」，備份還原後仍可讀取；舊連結未記錄來源名稱時沿用 Google Drive，不猜測其原帳號。來源名稱的快照不參與檔案身份，原關聯及跨來源去重規則保留。

## 授權續接

| 操作或狀態 | 行為 |
| --- | --- |
| 首次連線或明確切換帳號 | 顯示 Google 帳號選擇流程 |
| 重新授權既有來源 | 使用已知帳號提示及 `prompt: ''`，減少重複提示；Google 仍可能要求登入或同意 |
| 回傳不同帳號 | 拒絕接續並提示使用原帳號，或明確按「切換帳號」 |
| 接近到期 | 到期前五分鐘顯示「即將到期」，可由側欄或設定重新授權 |
| 已到期 | 只停止該來源讀取，顯示續接入口；其他有效來源與任務資料保留 |
| 關閉、拒絕或無法開啟授權視窗 | 顯示原因及重試入口，不自動反覆彈窗 |

Google 連線頁的檔案瀏覽也分開提供重新授權與切換帳號。頁首 G 在主要服務使用同一已知帳號時採續接流程；各主要服務使用不同帳號時，提示到設定分別重新授權。額外檔案來源由自己的入口續接，不被主要合併授權覆蓋。

此階段仍由使用者按鈕觸發授權。完全無互動的憑證更新另列後端里程碑，原憑證期限不延長。參考 [Google JavaScript API](https://developers.google.com/identity/oauth2/web/reference/js-reference) 與 [Token Model](https://developers.google.com/identity/oauth2/web/guides/use-token-model)。

## 保存、相容性與驗收

新增公開設定使用 `iih-orbit-drive-sources-v1`，包含來源識別、服務、名稱、Client ID 及已確認帳號；來源名稱與額外連線設定不進任務 JSON 或日常同步。各來源的憑證、失效識別、授權紀錄及分頁訊息使用獨立命名空間，驗證帳號、Client ID、scope、資料世代與原期限後接續。

既有主要來源仍使用原憑證與帳號鍵，不重新編號任務來源、關聯事件或 Drive 備份。設定保存失敗保留原設定；其他分頁移除來源後，舊授權不能重新建立來源。同步並登出會清除所有檔案來源憑證，沿用既有成功保存後才清理本機資料的流程。

本機測試以合成 OAuth／API 回覆驗證帳號與憑證隔離、來源切換、分頁接續、取消、保存失敗及相容性；手機尺寸檢查使用獨立測試頁。真實 Google 多帳號、不同 Cloud 專案、共用位置及實體手機操作仍須實際驗收。
