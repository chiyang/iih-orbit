# 任務與月曆提醒設計

[文件索引](README.md) · [使用指南](user-guide.md)

目前已完成截止篩選、跨工作空間的程式內訊息提醒、提醒歷史、右下角開始提示及使用者自行啟用的系統開始通知，整合待完成任務與 Google 活動。固定採純前端、無後端；系統通知在程式開啟期間排程，實際作業系統及手機支援須分開驗收。

## 已實作

- 工作區有「已逾期」與「1／3／7／30 天內到期」快捷篩選，以及任務日期下拉選單；同時套用到看板、清單及本機任務日曆。快捷天數只影響目前分頁的檢視，不修改保存的預設值。
- 日期下拉選單的「未設置」篩選截止日期空白的任務，包含已設定開始日期的項目。保留目前狀態範圍及其他篩選，清單預設沿用看板順序，不自動切為待完成；選擇隨本機瀏覽狀態保存。
- 工作區及右側訊息提醒都有「本週任務」。依目前本機日期的週日至週六計算，包含排程與這一週重疊的待完成任務；只有開始或截止日期也可列入，排除完成、封存及未排程任務。日期未指定時間時涵蓋整日；指定時段在週日午夜結束且未進入新週的項目排除，零長度時點仍可列入所在週。範圍用日曆日期計算，支援跨月、跨年與夏令時間。
- 截止篩選只計入一般待完成任務，排除已完成、封存及沒有截止日期的任務。指定時間依該時刻判斷，沒有時間依當天結束判斷。
- 即將到期從目前時間往後計算，預設三天，可在「設定 → 任務提醒」改為 1–30 天。例如 10 月 9 日 12:00 的三天範圍包含 10 月 12 日 12:00 的截止時間。
- 清單在截止篩選下預設按截止時刻升冪；即將到期最接近截止的任務排前面，已逾期則最早的截止排前面。可點表頭改用其他排序，還原後回到截止排序。
- 本週篩選的主畫面清單預設按開始日期升冪，只有截止日期的任務置後；右側本週列表依開始時刻排序，沒有開始日期時用截止時刻。右側顯示完整起迄範圍，只有截止日期的項目標示「截止」。
- 快捷數字代表目前工作空間全部待完成任務；篩選結果仍會與搜尋、專案及分類條件交集。篩選不改動任務、進度或 Google 活動。
- 主畫面任務日期篩選期間月曆及週視圖暫時隱藏 Google 活動，外部活動不參與逾期判斷；清除篩選後恢復原先的 Google 顯示選擇。右側本週列表則包含已綁定且顯示的 Google 活動，沿用真實活動時刻及 Google 全天結束日不包含當日的規則。Google／Orbit 快捷開關只改變顯示，不修改來源或同步設定。
- 截止範圍與右下角提示設定隨本機分頁同步及全部備份保存。舊設定只有天數時，自動補齊開始提示偏好。匯入工作空間副本保留本機提醒偏好；清空工作資料保留偏好，重置整個 Orbit 還原預設。系統通知偏好另存目前瀏覽器，不納入備份。

## 程式內訊息提醒

右側訊息提醒預設彙整全部工作空間，分成「今日開始、明天開始、本週任務、下週開始、N 天內到期、已逾期」，可切回「目前空間」。主畫面的截止篩選及快捷數字仍維持目前工作空間；提醒側欄的「查看目前空間清單」也只開啟該空間的主畫面。提醒清單不受主畫面的搜尋、分類、專案或日期篩選影響；Google 使用來源的綁定與顯示偏好。主畫面本週篩選及右側目前選擇的提醒分頁隨瀏覽狀態保存在本機，重新整理可接續；跨入週日後重新計算本週。

各工作空間使用自己的自訂狀態判斷待完成任務，項目標示所屬空間及分類色；不同空間的相同任務識別不互相覆蓋。Google 近期提醒讀取所有仍有工作空間綁定且顯示的來源快取，同一活動綁定多個空間只列一筆，標示所有所屬空間；切換目前空間不重複送出開始提示。月曆主畫面仍只呈現目前空間的活動。點選其他空間的任務或活動時，切到所屬空間後開啟最新內容，保留提醒側欄；編輯中的草稿、已移除的空間與垃圾桶項目不被舊提醒覆蓋。

頁首多功能按鈕只對尚未查看的新提醒顯示鈴鐺與數字，仍依「衝突 → 新提醒 → 新郵件」決定圖示；衝突沿用三角形警示圖示，不額外標示新項目，同一任務／活動去重。徽章與開始提示涵蓋全部工作空間。前景開啟「近期提醒」後，所選空間範圍內的近期提醒視為已查看，收起對應徽章而保留清單；選「目前空間」不替其他空間標為已查看。這次瀏覽的新項目顯示「新提醒」，保留至關閉或切換離開提醒側欄，切換提醒日期、開啟明細或暫時遮住側欄不清除。側欄隱藏、歷史檢視、中央對話框開啟或分頁在背景時，不把新收到的提醒視為已查看。新增、時程變更或進入今日／即將到期／逾期等狀態時可再提示，標題與描述修改不重新提示。提醒入口優先開啟含有新提醒的範圍。

查看識別包含資料世代、工作空間、項目、起訖時程及提醒階段，最多保存最近 5000 份於 `iih-orbit-reminder-seen-v1`。不保存標題、描述或憑證，不備份或跨裝置同步；同來源分頁透過儲存事件及取得焦點接續，寫入沿用本機寫入鎖合併。保存失敗仍在當前分頁收起徽章並顯示提示，重新開啟可能再次提醒。

| 類別 | 對象 | 排序與操作 |
| --- | --- | --- |
| 今日／明天／下週開始 | 有開始日期的待完成任務、已綁定且顯示的 Google 活動，含全天 | 依開始時刻升冪；本機開啟編輯，Google 開啟活動明細 |
| 本週任務 | 排程與本週重疊的待完成任務、已綁定且顯示的 Google 活動，包含跨週及單一日期 | 依開始時刻升冪，沒有開始時刻時使用截止時刻；顯示完整日期範圍 |
| 即將到期 | 提醒範圍內的待完成任務 | 依截止時刻升冪，可直接切換截止清單 |
| 已逾期 | 已過截止的待完成任務 | 依截止時刻升冪，最久未完成者排前面 |

明天採本機下一個日期，下週是下一個週日至週六，顯示實際起迄日期，包含跨月及跨年。開始列表的全天安排依開始日期列入，不在午夜發出提示；跨日項目只在開始日列入，僅設定截止日期的任務不列為開始。本週列表則依範圍重疊判斷，已開始但仍排程在本週的任務也列入。今日保留未開始、全天及剛開始五分鐘內的項目。訊息提醒提供 1／3／7／30 天的到期切換，也可直接切到主畫面的截止清單。本週列表不增加新的自動提示，開始提示維持既有規則。

訊息提醒在共用右側欄呈現，可與 Gmail 切換；各列表同時包含兩種來源時，才在列表前提供全部／Orbit／Google 篩選；Orbit 使用任務分類色，Google 使用月曆來源色。開啟中央任務／活動明細不會關閉面板，中央視窗開啟期間面板暫停操作，關閉明細後可繼續查看其他項目。

Google 月曆多選只在目前日期範圍包含多個月曆、且正在顯示 Google 時提供；選項依篩選前的列表產生，包含來源顏色及活動數，可全選／全部取消，勾選立即更新列表。今日、明天、本週、下週及到期列表各自保存篩選選擇，範圍按鈕保持原始總筆數，列表顯示篩選後／原始筆數。這些條件只在訊息提醒本次開啟期間使用，不變更主畫面顯示、Google 綁定、同步或保存的來源偏好；切換工作空間及重置資料會回到全部。新出現的月曆預設納入；當來源或月曆減至單一時，隱藏的控制不會留下無法恢復的空列表。

Google 提醒從共用快取讀取，展示來源與唯讀標記；同步狀態統一從側欄查看，訊息提醒不重複列出。近期月份有獨立查詢需求，瀏覽其他月份不會換掉近期提醒；涵蓋的範圍共用既有查詢，跨月才調整需求。來源被隱藏、解除所有空間綁定或帳號切換後立即移除；離線與授權到期時由側欄標示快取狀態。沒有快取時側欄顯示需連線或尚未讀取，不推算未知活動。完成、封存、刪除或改期後立即重算提醒。

## 提醒歷史

2026-10-17 第三階段加入「近期提醒／提醒歷史」切換。歷史從新版開始累積：程式在前景觀察到新的近期提醒，或將系統開始通知交給瀏覽器時保存一筆，改期或進入新的提醒階段可新增；開始提示顯示及關閉狀態補記在對應紀錄。這是實際觀察到的提醒歷史，未開啟程式、未觀察到的背景期間與舊任務不回推漏失紀錄，不代表系統通知已送達。

紀錄保存當時的任務／活動名稱、工作空間名稱、開始／截止時程、提醒階段及時間，另記已讀、開始提示顯示與關閉時間，以及交給瀏覽器發送系統通知的時間；不保存描述、郵件正文或憑證。系統通知的發送標記不代表系統已顯示、使用者已收到或已閱讀。之後改名、完成、封存、移入垃圾桶、永久刪除或移除工作空間，不改寫當時的快照。仍存在且未在垃圾桶的 Orbit 任務可開啟目前內容，包含已完成或封存任務；Google 僅在目前綁定及快取仍可解析該活動時開啟目前的唯讀明細，否則只顯示歷史。

歷史可選全部／目前空間、只看未讀、逐筆或「全部標為已讀」，每次先顯示 30 筆，再按「顯示更多歷史」。開啟開始提示或歷史項目會標為已讀，單純關閉提示不代表已讀。瀏覽歷史本身不自動替新收到的近期提醒消除徽章；標為已讀只更新選定紀錄的識別，不誤確認改期後的新提醒。

`iih-orbit-reminder-history-v1` 在這個瀏覽器保留近 30 天、最多 500 筆，不加入 JSON／Drive 備份或跨裝置同步。同來源分頁沿用寫入鎖合併，以儲存事件及前景更新接續，避免互相覆寫。資料世代隔離舊歷史；重置清理，登出沿用本機資料清理。等待中的舊世代寫入會取消，不在重置後復活。保存失敗會在提醒側欄說明，近期清單及原工作資料保留。

## 右下角開始提示

- 預設啟用，有時間的安排提前 30 分鐘提醒，可選 15／60 分鐘；保留已儲存的既有偏好；開始後五分鐘內返回前景仍可補提示，較早的已開始項目不再打擾。
- 全天安排預設當日 09:00 後提示一次，時刻可修改。若當天稍晚才開啟程式，仍可提示全天安排，當天結束後停止。
- 設定可關閉全部提示或只關閉 Google 提示，訊息提醒清單仍可查看。只在前景且有焦點的分頁顯示；編輯／管理視窗開啟時暫緩，不覆蓋未保存的草稿。
- 最多三則，點選可開啟對應任務／Google 唯讀活動，亦可關閉或開啟訊息提醒；沒有強制自動消失。時程失效、改期、完成、封存、刪除或來源隱藏後移除。
- `orbit-reminder-delivery-v1` 保存提示識別與到期時間，透過既有 Web Locks／IndexedDB 寫入協調，只讓一個分頁取得同一提示。識別含資料世代、工作空間、項目及開始時刻；重新整理不重複，改期可重新提醒。
- 去重記錄不保存標題、描述或憑證，也不納入備份；重置清理，過期記錄在下次提示時移除。保存或協調不可用時暫停自動提示並在訊息提醒說明，仍可手動查看清單。
- 此開關只控制程式內提示，不要求 Notification 權限；系統通知有獨立開關及去重紀錄，可自行決定是否同時啟用兩種管道。

## 系統開始通知

2026-10-18 第五階段加入「設定 → 任務提醒 → 系統開始通知 · 此瀏覽器」。預設停用，只有使用者明確點擊「啟用系統通知」才要求瀏覽器權限；允許後可按「發送測試通知」。拒絕、略過或不支援時仍可使用程式內提醒。封鎖後須先到瀏覽器網站設定允許，再回來啟用；程式不反覆要求權限。

測試結果緊接按鈕下方，每次手動測試使用新的通知識別，避免只替換舊通知。結果表示已交給瀏覽器，實際顯示與聲音仍依作業系統設定。

系統通知彙整全部工作空間，不受主畫面的篩選影響。提前時間可選 15／30／60 分鐘，全天預設當日 09:00，可獨立設定是否包含已綁定且顯示的 Google 活動。使用現有本機資料與 Google 快取，不為通知發起額外授權或查詢。編輯、管理視窗或來源拖曳期間暫緩；有時間的安排只補開始後五分鐘內的提醒，全天只在當日補送。每輪最多三筆，後續排程接續尚未處理的項目，不集中補發久遠通知。

偏好存於 `iih-orbit-system-notifications-v1`，只影響目前瀏覽器，同來源分頁可接續；不加入 JSON／Drive 備份或跨裝置同步，不因匯入備份替其他裝置啟用通知。清空工作資料保留開關但更新資料世代；重置整個 Orbit 或同步並登出會清除偏好。系統通知可能在螢幕或通知中心顯示任務名稱與工作空間，設定內有明確說明。

`iih-orbit-system-notification-delivery-v1` 透過共用寫入鎖，在呼叫通知 API 前保留該項通知的識別；同來源多分頁及重新整理不重複發送，改期可再提醒。識別含資料世代、工作空間、項目、開始時刻及 Google 帳號脈絡，不保存標題、描述或憑證；與右下角提示的去重分開。紀錄過期後回收，最多 2000 筆有效紀錄；損壞、滿額或無法協調／保存時暫停，不清空紀錄冒險重送。已知 API 拒絕時釋放自己的保留並稍後重試；在呼叫途中關閉分頁等結果不明情況，保留識別到期，因此可能漏送一次，而不盲目重送。發送失敗可在設定內看到說明，程式內清單仍可查看。

點擊通知時，已有 Orbit 視窗則切回並解析最新任務；沒有視窗則開啟 PWA 範圍內的首頁，待本機資料載入後接續。傳遞識別、不接受任意外部網址。正在編輯時先保留開啟要求及草稿，完成或取消後才開啟。已移除、垃圾桶、舊資料世代或 Google 帳號／來源不符的通知不開啟過期內容。點開才標為已讀，單純發送不代表閱讀。完成、刪除、改期、來源隱藏、停用或撤銷權限時，會嘗試收起失效通知；實際通知中心仍由作業系統管理。

正式 PWA 優先使用目前 Service Worker 的 `showNotification()`；無已啟用的 Service Worker 時，桌面環境使用 `Notification` 建構子。測試通知不加入任務歷史。歷史的「已交給瀏覽器發送系統通知」僅代表 API 接受發送，不能保證作業系統顯示或發聲。

## 純前端與裝置限制

手機不能直接假設 `new Notification()` 可用，多數手機瀏覽器需透過 Service Worker 的 `showNotification()`。Service Worker 也不是持續執行的定時服務；不能承諾關閉頁面或手機背景限制下仍會準時提醒。[Notification 建構子限制](https://developer.mozilla.org/en-US/docs/Web/API/Notification/Notification)、[背景執行機制](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Offline_and_background_operation)

背景 Web Push 通常由伺服器傳送訊息。本工具目前沒有後端，因此系統通知定位為「程式開啟期間提醒」。分頁在背景會嘗試發送，但瀏覽器節流、裝置休眠及關閉程式都可能延後或停止排程；不保證準時或補送超過期限的提醒。Service Worker 負責離線啟動、資源快取及通知點擊，不持續計時，也沒有新增 Push 訂閱或伺服器。若將來需要關閉程式仍可靠提醒，可另評估原生封裝或獨立推播服務；目前不加入此依賴。[Push API 說明](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)

## 後續實作順序

1. 跨工作空間檢視、已讀狀態與提醒歷史已完成，後續依實際使用回饋調整。
2. 系統通知的使用者啟用、測試通知、分頁去重、點擊接續及歷史已完成。自動化涵蓋拒絕權限、改期、重置、晚到回應及睡眠返回的時限；隔離瀏覽器以合成通知驗證設定與操作，不視為真實系統通知驗收。
3. 仍需在實際桌面及手機 PWA 驗證權限、顯示、聲音、通知中心點擊及背景限制；維持關閉頁面時不保證定時通知的說明。
