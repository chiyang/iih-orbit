## 使用者操作

自動儲存仍涵蓋全部工作空間，沿用目前 Google Drive 連線、同步按鈕、共同祖先整併及內容選擇。沒有新增 Google 授權範圍。

本機匯出仍是一個可獨立還原的完整 JSON，備份格式 5、20 MB 上限及現有匯入預覽／全部還原／加入副本流程維持原樣。手動另存至 Drive 的獨立備份也保留完整 JSON。

新版自動同步在 Drive 保存的是版本索引與共用資料區塊。若要取得可攜備份，請在 Orbit 下載 JSON；只下載 Drive 的索引檔無法獨立還原。不要單獨移除「共用資料區塊」的內容。

## 本機保存

核心資料遷入 IndexedDB `iih-orbit-workspaces-v1` 的 `records` 儲存區：

| 紀錄 | 保存內容 |
| --- | --- |
| 根索引 | 世代、修訂、設定、工作空間順序與預設選擇 |
| 工作空間索引 | 工作空間 metadata、各類實體的識別與順序 |
| 實體紀錄 | 任務、專案、分類、狀態、任務衝突與 Calendar 移轉紀錄 |

同一個讀寫交易重讀最新資料、檢查原始版本、驗證變更，再只寫入變動紀錄。單純修改一個任務通常只更新任務與根索引；新增／刪除／排序另更新相應索引。交易中斷不留下部分更新。

`orbit-workspaces-v2` 改存小型 `formatVersion: 3, storage: indexeddb` 通知，保留世代與修訂，不再反覆序列化全部任務。分頁仍透過 BroadcastChannel、storage 事件及取得焦點重讀。分頁工作空間選擇與舊草稿檢查沿用既有行為。

升級先驗證舊 localStorage 資料，寫入成功後才發布通知；保留原世代、修訂、設定及分頁選擇。支援 Web Locks 時，升級期間沿用舊寫入鎖直到交易及通知完成。升級失敗保留舊來源並提示，不以空白資料覆蓋。載入期間顯示狀態，引導、瀏覽偏好及 Google 服務初始化等待核心資料完成，避免暫時空白狀態清除原連線或同步基準。

更新時須重新載入所有舊版分頁；不支援 Web Locks 時，升級前尤其需要關閉舊分頁。已升級的通知不再是舊版可寫回的完整工作資料。沒有 IndexedDB 的既有環境保留原儲存流程，但不能寫回已升級資料。

## 雲端版本

新自動備份／同步使用雲端格式 5；實際索引為 `iih-orbit-chunked` 格式 1，區塊為 `iih-orbit-block` 格式 1。這些版本與本機完整 JSON 的格式版本各自獨立。

每個工作空間拆為一個 metadata 區塊，以及最多 64 個任務分組。任務按穩定識別分組，組內按識別排序；原任務順序另外留在版本索引。一般任務內容修改只改一組，純任務排序只改索引，避免一個任務一個雲端檔案。metadata 仍包含專案、分類、狀態、衝突及移轉紀錄；這些內容修改會更新該工作空間的 metadata 區塊。

每份版本索引列出完整的當前區塊組合、共享設定、邏輯內容校驗與原有父版本關係，無須回放無限長的差異鏈。相同集合內相同內容的區塊以 SHA-256 辨識並重用；不同集合分開查找。

保存順序：

1. 先保存小型 `pending-version` 暫存索引（`iih-orbit-upload`），記錄本次需要的區塊摘要。這份索引沿用待上傳檔案 ID，供其他裝置辨識保護範圍，尚不列為可用備份。
2. 讀取完整區塊索引，遇到不完整分頁停止發布。
3. 重用未變區塊，最多四個並行請求保存新區塊；觀察中及垃圾桶內的區塊不重用，從本機完整資料另存可用副本。
4. 比對實際保存大小及 Drive 提供的 SHA-256；沒有服務端校驗值時下載讀回驗證。
5. 必要區塊全部完成後，補完暫存索引；發布前再核對引用仍可用，最後將類型改為正式版本。中途區塊被隔離時，最多重建三輪，仍不能完成就保留佇列重試。單次區塊發布作業逾五分鐘或裝置時間倒退時拒絕繼續，避免休眠很久後發布過期引用。
6. 失敗保留本機完整待上傳版本；回覆遺失後可找回已完成區塊，沿用版本及檔案識別重試，已發布的完整版本不改寫。暫存索引的本文每次重試更新，讓 Drive 的內容修改時間反映最新作業；不包含任務本文或授權憑證。

SHA-256 欄位的可用性依 [Google Drive 檔案欄位](https://developers.google.com/workspace/drive/api/reference/rest/v3/files)；程式保留讀回驗證的備援。

讀取時先驗證索引，再取得缺少的區塊，核對區塊校驗、識別與排序，組回完整資料並驗證原有整份備份校驗。區塊遺失、竄改或內容不合法時，不套用資料。已驗證同步基準可重建未變區塊快取；快取隨帳號／連線切換清除，並有數量與記憶體上限。

舊雲端格式 1–4 的完整 JSON 繼續讀取，舊內容與校驗不改寫；下一次共享內容修改才建立新格式版本。共同祖先、並行分支、衝突選用及垃圾桶中的祖先資訊維持原則。其他裝置須更新至可讀雲端格式 5 的版本才能接續。

## 歷史與清理

同步完成後先更新清單，資料夾整理與過舊版本清理延後至少五秒，並等待本機待寫入、同步與自動儲存等待流程結束。維護占用作業鎖時，新的自動同步會重新排程，不丟掉待處理的修改。手動重新載入、整理及首次設定仍可執行維護。

最近八份仍按邏輯版本計算。保留同步基準、待上傳父版本及未處理分歧；移至垃圾桶的索引保留祖先資訊，共用區塊不跟著刪除，因此歷史仍可讀取。

### 未引用區塊的 30 天觀察

自動回收已實作，僅處理具有 Orbit 標記、正確集合識別與摘要的資料區塊。原本一般區塊為 `block`；完整掃描確認沒有引用後，改為 `orphan-block`，保存新的觀察識別與 `gcSince`。從首次完整檢查開始等待 30 天，不使用檔案建立時間直接判定到期。

掃描保護所有仍可讀的正式版本，包括最新、分歧、垃圾桶內歷史及集合刪除識別所保留的內容。最近 30 天仍有進度的暫存索引，另保護需要的區塊摘要；未完成的空索引先保護整個集合。過期暫存作業不永久阻擋清理，本機佇列仍保留完整資料，裝置回來後重新建立可用區塊。

觀察中的區塊仍可供既有版本讀取，但新上傳不再引用它。若掃描發現重新被引用，先保留並取消原期限；之後再次失去引用，重新開始完整 30 天觀察。清理前重新掃描引用，逐份核對觀察識別、期限、集合及內容摘要；清單不完整、格式異常、帳號或作業狀態改變就停止，不以不完整清單推測孤立資料。

觀察時間取自 Drive：`IIH Orbit/區塊維護紀錄.json` 每次只更新隨機識別，取得內容修改的服務端時間，完整引用掃描後再次確認時間，再寫入觀察記錄。紀錄不含工作資料或憑證；裝置時鐘偏差不會讓 30 天提早到期。Drive metadata、appProperties 清除與時間欄位依 [Google 檔案欄位](https://developers.google.com/workspace/drive/api/reference/rest/v3/files)。

### 分批執行與結果

每輪最多更新 100 筆觀察記錄、移動 20 個到期區塊。尚有待處理批次時至少五分鐘後再執行；全部檢查完成後約每 24 小時再掃描，失敗約十五分鐘後重試。這些間隔是目前分頁的排程，重開後可以再次檢查；沒有 Orbit 開啟、未連線或離線時不執行。

清理排在雲端清單讀取後的閒置時間，本機待寫入、自動同步等待或其他 Drive 作業中都會延後。它沿用同來源 Drive 作業協調，但沒有宣稱取得跨裝置互斥鎖。清理失敗顯示獨立警告，不把已完成同步改成未保存；成功移至垃圾桶後顯示筆數。部分失敗只接續剩餘內容，不重新移動已處理檔案。

只移至 Drive 垃圾桶，不永久刪除、不清空使用者垃圾桶；垃圾桶仍占空間，Drive 一般在移入後 30 天永久移除才釋放容量。[Google 垃圾桶說明](https://support.google.com/drive/answer/14933051?hl=en)

刪除整個集合仍保留停止同步識別及垃圾桶中版本需要的區塊；待引用消失後才進入上述觀察。未完成的暫存索引是小型保護紀錄，本輪只回收其不再需要的資料區塊，尚不另行刪除暫存索引本身。最近八份仍是邏輯版本數，不是實體檔案數。

長期離線後，可從本機完整資料補回已回收區塊；但這不代表一定能自動整併所有分歧。若必要共同祖先已不可讀，仍保留本機資料，沿用原有接續選擇，避免直接覆蓋其他裝置內容。

## 驗證與效能界線

621 項自動測試通過，另以獨立來源的原生瀏覽器完成 18 項檢查。包含一千任務升級、每筆寫入、多分頁修改、過期草稿、交易中斷、容量不足、完整還原、舊世代阻擋，以及登出後重新載入。雲端使用模擬 API 驗證重用、冷讀、校驗失敗、中斷重試、版本整理及歷史清理，另涵蓋三十天精確邊界、分批回收、重新引用、清單異常、服務端時間、過期作業重建及背景重試；詳見 [QA](../QA.md)。

一萬任務的合成資料（識別為 `task-0` 至 `task-9999`，每份描述為 40 次「內容」）只改一筆標題：

| 指標 | 結果 |
| --- | --- |
| 原完整 JSON 資料量 | 4,349,460 bytes |
| 新增一個區塊＋版本索引＋暫存保護索引資料量 | 198,968 bytes |
| 減少的資料量 | 95.43% |
| 持有已驗證前版基準的接收裝置 | 一份索引＋一個變動區塊 |

此表只計 JSON 本文，不含 HTTP／multipart 封裝、metadata 更新、列舉回覆及網路延遲。不同識別長度、描述、工作空間或修改範圍會改變比例。首次同步及大量修改有額外請求，可能較慢。

本機差異檢查、完整邏輯校驗與共同祖先整併仍需掃描或組回資料；目前主要改善實際寫入與網路傳輸，不能宣稱 CPU 成本已完全按變動量計算。尚未完成真實 Google Drive 的端到端效能或跨裝置驗收；20 MB 完整備份上限也仍保留。
