# 任務雙欄編輯、連結用途與排序

[文件索引](README.md) · [本輪改版規劃](task-hub-next-release-plan.md)

2026-10-15：本輪第二階段已實作。

## 使用方式

- 寬畫面左側放任務名稱、釘選、專案、分類、狀態、優先順序與描述；右側放資訊連結、時程與子任務。表單只有一個主要捲動區，標頭及底部儲存／取消保持可及。
- 版面依容器可用寬度與字級切換；窄畫面、大字級自動改為單欄，最窄時基本欄位也改成單欄。切換尺寸不重建編輯器，保留草稿與專注編輯模式。
- 螢幕至少 1280 × 640px 時，右上角提供「全畫面編輯／還原編輯視窗大小」按鈕。放大後四周保留 16px 遮罩邊界，標頭及儲存／取消固定可及，內容在視窗內捲動；切換保留未儲存草稿，每次重新開啟任務使用預設大小。視窗縮小時自動沿用原本的響應式版面。
- 郵件與檔案連結可按「新增用途說明／編輯用途」，填寫最多 1,000 字的純文字；「完成說明」回到閱讀狀態，仍屬任務草稿。空白說明不額外佔行。
- 拖曳左側把手或按上下箭頭排序；檔案、資料夾與郵件共用一份順序。新項目附加在末端，重新選檔會保留既有混合順序及用途。
- 按「儲存變更／建立任務」後生效；取消任務不保存用途或排序。獨立選檔的取消及 Escape 只關閉內層，保留任務草稿。連結名稱與 ↗ 繼續在原服務開啟。
- 用途屬於這個任務與來源的關係，同一文件可在另一個任務寫不同說明；不改原檔名或郵件主旨，也不建立自訂別名。
- 相關任務也整合在「資訊連結」內，計入該區總數。按「建立任務連結」開啟搜尋／複選視窗，加入同空間其他專案的任務；相關任務列提供開啟及解除操作，郵件／檔案的用途與混合排序不套用到這些列。選取與解除先保留在草稿，儲存任務後才生效。[任務連結操作](related-tasks.md)。

## 描述編輯與本機草稿

描述文字區預設至少 360 px，可向下拉長；「專注編輯」提供更大的編輯空間。Tab 插入兩個空格，選取多行時一起縮排；Shift+Tab 移除縮排。要用鍵盤離開描述區，先按 Esc 再按 Tab。Esc 不會關閉任務或離開專注編輯，內層 Drive 選檔仍可用 Esc 取消。

停止修改約 1.2 秒後，名稱、描述、時程、子任務、已選郵件／檔案／相關任務連結、用途／排序及尚未加入的文字輸入會自動保存成本機草稿。畫面顯示等待、已暫存或保存失敗；草稿獨立於正式工作資料，不改任務更新時間、復原歷史或同步版本，也不因暫存發出 Google／Drive／Calendar 同步。既有同步仍可處理其他已正式保存的資料。

點擊任務編輯視窗外側的遮罩不會關閉，使用右上角 × 或「取消」離開。重新整理或用右上角關閉後，再開啟相同任務會出現「恢復草稿／捨棄這份草稿」；新任務草稿在同一工作空間的新增任務入口恢復。按「取消」會捨棄這次編輯及其本機暫存；成功按「儲存變更／建立任務」才正式套用並沿用原本同步流程。建立文件及移至 Calendar 仍須先正式保存。

草稿保存在此瀏覽器網站資料中，不隨 JSON／雲端備份移動；清除網站資料或同步登出會移除。各工作空間及資料世代隔離，每次編輯使用獨立紀錄，其他分頁的草稿不被覆寫。恢復時保留原編輯基準，正式任務已被其他分頁修改、刪除或連結已更新時，須載入最新版本或另存新任務，不能直接覆蓋。最多保留 50 份、單份最多 2 MB；空間不足時明確提示，不宣稱已保存。

## 復原、複製與並行修改

復原／重做涵蓋用途、順序及連結本身；草稿另存新任務與工作空間副本會保留用途、順序，副本的任務及新增事件使用獨立識別碼。移到垃圾桶不丟失連結內容。

儲存解除關聯後再加入，會建立新事件、使用空白用途並排在末端；復原解除則恢復原用途與位置，並把用途綁到新的有效事件。舊裝置對已移除事件的說明修改不會套到重新加入的關聯。

跨裝置以共同版本作三方整併。不同連結／任務的用途可合併，一台改用途、另一台改順序也可合併；同一用途的不同修改或互相矛盾的重排會保留雲端分支供選擇，不按裝置時間決定。雲端內容預覽可展開各任務的資訊連結，按編號查看用途及順序；衝突副本另有「預覽」，原本的直接採用雲端按鈕仍維持直接套用。

## 保存與格式

| 資料 | 用途 |
| --- | --- |
| `documentSources` | 來源身份、URL、名稱及位置快照 |
| `documentLinks` | 每次新增的事件與永久移除標記 |
| `documentDetails` | 以任務／來源識別的一份用途，及它適用的新增事件 `linkIds` |
| `documentOrders` | 每個任務的來源識別排列；重複新增事件仍只呈現一項 |

用途與順序至少需要看板格式 **6**、JSON 備份及 Drive 雲端格式 **7**（索引標記 `v7:`）。含完成歷史時至少為看板 7／備份 8，含相關任務時為看板 8／備份 9；依實際資料採用所需格式，不因編輯用途而降版。未使用新欄位的舊資料維持原格式，仍可讀取舊備份並驗證原校驗；不在讀取歷史檔時補寫新欄位。

IndexedDB 逐筆保存用途及順序；自動 Drive 備份納入原有分塊機制，手動 JSON／Drive 備份仍能單檔還原。新格式的 JSON、雲端索引與看板版本會讓不支援的舊程式停止讀取；新程式也拒絕用舊格式包裝新欄位。所有接續裝置須支援實際使用的格式；含相關任務時須支援格式 9。[完整格式與備份範圍](backup-and-sync.md)。

本機控制器與模擬 Drive API 測試包含並行修改、生命週期、備份及副本；實際 UI 使用獨立來源與合成資料驗證。真實 Google 跨裝置同步與實體手機仍待驗收，詳見 [QA 紀錄](../QA.md)。
