# 從任務建立文件與安全來源整理

[文件索引](README.md) · [多個 Drive 檔案來源](drive-file-sources.md) · [檔案資訊更新](document-information-refresh.md)

2026-10-15：完成本輪第四階段。可從任務建立 Google 文件、試算表與簡報，並整理完全沒有引用的文件來源紀錄；同日後續補上 Colab 空白 Python 筆記本。任意內容／模板上傳、其他服務文件建立及歷史永久壓縮未包含在本階段。

## 建立並連結

1. 打開任務，在「資訊連結」按「建立文件」。
2. 新任務或草稿有修改時，先明確按「儲存任務並繼續」；也可選「繼續編輯」保留草稿。保存失敗、日期不合法或有其他分頁衝突時，不進入建立流程。已保存且沒有修改的任務可直接進入，不另存一次相同版本。
3. 選擇檔案來源、Google 文件／試算表／簡報／Colab 筆記本（Python）、名稱與保存位置。名稱預設為任務名稱，最多 300 字；各來源記住最後成功的保存資料夾。
4. 按「建立並連結」，必要時由 Google 取得該來源的建立授權。建立成功後直接保存任務關聯並顯示「開啟文件 ↗」，交由原 Google 編輯器編輯。

四種文件類型使用與檔案列表一致的彩色圖示，以可點選的單選卡片呈現；可用 Tab 聚焦、方向鍵切換。寬畫面兩欄、手機單欄，建立完成後也顯示對應類型圖示。

建立完成後，外層任務會帶回新連結與最新版本；此連結已保存，外層按「取消」不會撤銷已完成的文件建立。若要解除，使用既有移除連結並儲存任務；雲端原檔保留。建立不自動開新分頁，使用者可點清楚的外開入口，因此不依賴非同步彈窗。

## Colab 筆記本

文件類型選「Colab 筆記本（Python）」，沿用原有來源、資料夾、先保存任務及建立授權流程。名稱自動補上 `.ipynb`，已有副檔名（含大寫）不重複補，含副檔名最多 300 字。建立的是有效的 Jupyter v4.5 筆記本，含 Python 3 核心設定及一個空白程式碼儲存格，沒有程式碼、執行次數或輸出；不啟動 Colab 執行環境。[Colab 筆記本格式](https://research.google.com/colaboratory/faq.html)、[Jupyter 格式規格](https://nbformat.readthedocs.io/en/latest/format_description.html)。

Colab 以單次 multipart 新增要求一起保存 metadata 與固定空白筆記本內容，使用 `application/vnd.google.colaboratory`；不是只建立空的檔案殼，也不先建檔再更新。新增端點固定為 Drive files.create 的上傳入口，不接受使用者任意內容、現有檔案 ID、更新或刪除。[Drive multipart 上傳](https://developers.google.com/workspace/drive/api/guides/manage-uploads)。

建立完成、待接續項目、任務連結及右側檔案列表的開啟入口會使用 Colab 編輯器。資料仍保存原本的 Drive URL、檔案 ID 與 MIME，保持同一個文件身份及既有備份格式；重新整理與 metadata 查驗不會失去 Colab 開啟入口。回覆遺失仍查核同一操作識別，任務保存失敗仍只重新加入原筆記本，不重送上傳。現有三種 Google 原生文件仍使用原本的 metadata 新增方式。

## 保存位置與授權

支援「我的雲端硬碟」根位置，以及使用者選定且具有建立能力的資料夾。按「選擇 Drive 資料夾」直接使用目前來源的 Google OAuth 讀取授權載入站內列表，支援逐層開啟、路徑返回、搜尋目前位置、重新整理、「與我共用」及分頁載入。選擇器有獨立導覽與快取，不改右側檔案分頁的位置；只列資料夾，排除一般檔案、捷徑、垃圾桶及可辨識的 Orbit 備份位置。

選取時用同一來源的讀取授權重新查核實際名稱、resource key、共用硬碟識別與 `canAddChildren`。通過才帶回保存位置；拒絕會留在列表顯示原因，可選其他位置。也能進入資料夾後按「使用目前資料夾」；「與我共用」只是列表入口，不可直接當作保存位置。取消保留文件名稱、類型及原位置，Escape 只關閉內層選擇器，焦點回到入口。來源、連線版本、帳號、世代或工作空間變更會取消，晚到結果不套用。

**不需要 Google Picker、API Key 或 Cloud 專案編號。** 檔案來源已連線即可瀏覽；未連線先按「連線此來源」。選取只讀取資訊，不發出寫入授權或建立要求。原手動連結入口保留在更多選項，最後成功位置仍按來源及帳號／Client ID／世代隔離。

### 建立授權

列表沿用 `drive.metadata.readonly`。實際按「建立並連結」時才取得指定來源獨立的寫入授權：

- 首次建立到「我的雲端硬碟」根位置，使用 `drive.file`。
- 建立到既有資料夾，使用 `drive`；這是可管理整個 Drive 的較廣授權，由 Google 視窗明確取得同意，表單也會說明。這讓一般 OAuth 列表選到的既有位置可以作為新文件的父資料夾。原本的 `drive.file` 不代表任意可見資料夾都已授權。若同一頁已取得此來源的較廣授權，後續根位置建立可沿用。

寫入憑證僅保存在本次頁面記憶體，與檔案讀取及遠端備份連線分開。額外來源使用自己的 Client ID 與原帳號，回傳不同帳號時拒絕接續。拒絕授權保留任務與位置，不建立文件、不改存根位置；Google Cloud 同意畫面須包含實際使用的 scope，公開服務仍須符合 Google 的相應驗證要求。[Drive 授權範圍](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)。

即使寫入授權較廣，建立介面仍只允許新增支援的文件及固定欄位查核；Colab 只上傳固定的空白模板，禁止更新、刪除、檔案內容讀取及任意 API；備份服務仍維持獨立的 `drive.file`。真正建立前會再次查核資料夾能力、垃圾桶及備份標記。來源／帳號／Client ID／世代變更會解除舊寫入授權及請求，共用資料夾仍以實際能力為準。[files.create](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/create)。

## 失敗、逾時與接續

建立前先把操作識別與選項成功寫入本機，再發出一次建立要求。Google 文件、試算表與簡報不支援預先產生的檔案 ID，本版以專屬 `appProperties.iihOrbitDocumentOperation` 保存隨機操作識別，供同一來源／Client ID 查核。此標記與 Orbit 備份檔的標記及清理範圍分開。[Google 原生文件的 ID 限制](https://developers.google.com/workspace/drive/api/guides/create-file)、[自訂檔案屬性](https://developers.google.com/workspace/drive/api/guides/properties)。

| 情境 | 行為 |
| --- | --- |
| 建立紀錄無法保存、來源變更或指定資料夾不可用 | 不送出建立要求，保留任務 |
| 明確拒絕授權／建立 | 顯示失敗原因，可確認後再操作 |
| 網路中斷、逾時或服務錯誤，無法確認是否建立 | 保留待接續紀錄、停用同一任務再次建立；先按「查核建立結果」 |
| 查核剛好一份結果 | 使用同一個檔案 ID，保存任務關聯，不再 POST 建立 |
| 查核零份、多份或不完整 | 提供等待／核對原檔的入口，不推測尚未建立，不自動選一份或重送 |
| 文件已建立但任務保存失敗、被修改或刪除 | 保留檔案 ID／URL，提供「重新加入原任務」；加入前在寫入鎖內核對任務、來源、工作空間與資料世代 |
| 建立結果保存中本機儲存失敗 | 目前畫面仍保留已知文件入口，原先的未確認紀錄可於儲存恢復後查核 |
| 已建立的文件移至垃圾桶 | 查核顯示原因與原檔入口，需先在 Drive 還原；不重新建立替代檔 |

待接續項目同時出現在任務建立視窗與「設定 → Google Drive」。切換到原工作空間、任務及來源帳號後，可查核或重新加入。舊資料世代、移除的來源或已刪除任務不會被自動重建；已知文件仍可由原連結開啟。

若已自行在 Drive 核對，可以選「結束這次接續」，再按明確的確認按鈕；這只結束本機接續，保留原檔與已有關聯。畫面會提醒另建可能產生重複文件。其他分頁或晚到回覆不能把已完成／已結束的紀錄重開；晚到的已知文件結果仍保留入口。

## 無使用來源整理

「設定 → Google Drive → 無使用的文件來源」會核對全部工作空間，列出未被目前有效任務使用的來源與保留原因，可展開查看前 50 項及總數。按「整理可安全移除的來源」時，會在工作資料寫入鎖內重讀，再核對當下引用，只移除預覽範圍內仍然安全的項目，完成後顯示實際筆數。

以下來源均保留：

- 垃圾桶、其他工作空間或衝突候選涉及的來源。
- 仍被新增／移除事件、用途生命週期或排列紀錄引用的來源。
- 復原／重做快照、開啟中的任務草稿或待接續建立結果需要的來源。

本階段只移除完全孤立的本機來源紀錄，不刪除關聯事件或歷史快照、不解除帳號連線、不操作 Google 原檔。保存失敗保留原來源；確認期間新增引用的項目跳過或取消。來源整理會保存工作資料的新修訂，但不改任務內容或修改時間；與第三階段只清除可重建快取不同。

沒有為來源退役或永久事件壓縮新增資料格式。看板維持 6、JSON／Drive 維持 7；舊備份或其他裝置仍可能帶回孤立來源紀錄，屬於正常還原／整併，不代表已移除的任務關聯復活。需要保留事件的來源縮減、退役及永久壓縮仍另列後續設計。

## 本機資料與驗收邊界

建立紀錄使用 `iih-orbit-document-operations-v1`，保存操作識別、任務／工作空間與資料世代、來源帳號／Client ID、名稱／類型、位置、結果 ID／URL 與接續狀態；不含 token 或文件內文，不加入任務備份。所有未完成紀錄保留；已結束紀錄最多保留 30 天，總記錄上限 100 筆，額滿優先回收已結束紀錄，若全數未完成則先處理既有項目。最後成功位置另以 `iih-orbit-document-destinations-v1` 保存，按來源及帳號／Client ID／世代隔離。

本機快取清理不移除建立紀錄；正常同步並登出或清除網站資料仍會清除本機紀錄。重要的未接續結果可先由畫面保存原文件連結。更換網站來源或裝置時，文件仍在 Google Drive；本機建立紀錄及建立授權不會自動搬移。

本機測試涵蓋三種原生文件與 Colab、固定筆記本格式與 multipart、操作先保存、單次 POST、不同帳號拒絕、指定資料夾能力、逾時／部分成功／重載查核、晚到回覆與引用保護。獨立完整 App 使用正式 Angular 編譯與真正 IndexedDB；Google OAuth／API、回覆遺失及保存失敗採合成情境。真實 Google 授權、Cloud 專案設定、共用硬碟、網路與實體手機尚待驗收，詳見 [QA 紀錄](../QA.md)。
