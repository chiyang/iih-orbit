## 1. 設計時的起點與目前進度

改版前使用 localStorage：

| 資料 | 現有儲存位置 |
| --- | --- |
| 所有工作空間、任務、分類、狀態、任務順序、目前工作空間 | `orbit-workspaces-v1` |
| 字體大小 | `orbit-text-size-v1` |
| 舊版看板與升級前備份 | `orbit-board-v1`、`orbit-board-v1-backup` |

改版前每次修改保存整份工作空間資料，沒有跨分頁監聽或同時寫入協調，可能以舊資料覆蓋另一分頁。

階段 1 已加入 `orbit-workspaces-v2` 的世代與修訂識別、寫入協調、分頁通知及檔案匯出／匯入；目前工作空間改存每個分頁的 `sessionStorage`。階段 2 將字體、主題與主題色納入同一儲存記錄，全部備份格式升為 3，還原時一起套用；工作空間匯入保留全域外觀。階段 3 將公開 Google 設定、來源綁定與更新頻率納入同一記錄，備份格式升為 4，仍讀取格式 1–3。特定工作空間備份可附帶公開連線設定，匯入時需另行勾選才套用。Google 不要求 Client Secret，設定頁提供 Client ID 的建立教學及使用者授權。

階段 4、5 在 1.5.0 實作，備份格式升為 5，完整檔案加入公開 Drive 偏好，還原時先關閉自動處理。設定新增 Google Drive 分頁，側欄提供狀態及管理入口；Calendar 與 Drive 使用獨立授權範圍、sessionStorage 與失效識別。Drive 待上傳檔及基準使用獨立 IndexedDB，重置或全部還原清理；已完成的雲端版本不覆寫。1.6.0 依使用者要求加入自動儲存最近 8 份保留規則，過舊版本移至垃圾桶並保留同步所需的祖先索引。實作與驗證紀錄見 [QA](../QA.md)。

2026-10-11 調整字體大小為各瀏覽器的本機偏好，從新備份與同步摘要排除；含字級的舊檔仍可讀取與驗證，匯入及同步保留本機字級。主題及主題色繼續保存與同步。

同日加入以最近共同祖先為基準的自動整併，安全的不同欄位、任務及子任務修改一起保存。同一任務的衝突選項納入工作資料，於右側欄逐項選用；未處理的任務不阻擋其他任務同步。已選用紀錄保留以辨識晚到的舊版本，選用後的新修改繼續保留。設定、排序、引用或缺少可靠基準時仍提供整份內容選擇。字級及瀏覽視圖維持本機偏好。

版本 1.2.0 採用「工作空間內的專案分組」，不增加獨立專案看板。任務新增可選的單一專案歸屬，專案共用分類與狀態；標題改為工作空間名稱，所有專案的任務可同時顯示，也能篩選。舊專案標題升級為第一個專案，備份格式升至 2，仍支援格式 1 的舊備份。外部月曆仍以工作空間綁定，Drive 的備份及同步範圍維持工作空間層級。

## 2. 本次改版的主要決定

1. **先完成本機備份與同步，再接 Google。** 即使沒有 Google 帳號、沒有網路，任務管理仍可正常使用。
2. **Google Calendar 活動獨立保存，疊加到月曆與週視圖。** 使用「外部月曆」來源分組，不把每個活動轉成一般任務或任務分類。
3. **Google Drive 使用可見的 `IIH Orbit` 資料夾保存版本。** 使用者能在 Drive 查看備份；程式只管理自己建立或使用者授權的檔案。
4. **設定頁保存 OAuth Client ID，不保存 Client Secret。** 初期 Calendar／Drive 的未過期授權憑證暫存至分頁 sessionStorage，重新整理驗證後恢復，同來源分頁可接續。1.7.0 依後續需求，Gmail、Calendar 讀取／移轉及 Drive 現在都改用目前瀏覽器 localStorage，支援關閉重開與斷網重連；有效的舊分頁憑證驗證後遷移。所有服務均不延長原期限，憑證不進匯出檔或 Drive。目前規則見 [Google 連線設定](google-setup.md)。
5. **雲端同時修改時保留來源並自動整併安全修改。** 任務衝突保留為右側欄待選版本，不新增重複任務；設定或無法安全判斷的資料仍提供雲端內容選擇與複製工作空間。

Google 的瀏覽器授權流程使用 Client ID；Client Secret 是伺服器端流程才需要的資料。Client ID 可以隨備份攜帶，但匯入後仍須重新授權。[Google Client ID 說明](https://developers.google.com/identity/oauth2/web/guides/get-google-api-clientid)

## 3. 檔案匯出與匯入

### 匯出

使用帶有格式版本的 JSON 備份，提供兩種範圍：

| 匯出範圍 | 內容 | 匯入結果 |
| --- | --- | --- |
| 全部資料 | 所有工作空間、任務、子任務、分類、狀態、排序、外觀及可攜式 Google／同步設定 | 取代現有全部資料，必須確認 |
| 選定工作空間 | 一個或多個勾選的工作空間及其完整資料、外部月曆來源設定 | 新增工作空間，保留原有資料 |

備份包含格式識別、格式版本、應用程式版本與匯出時間。檔名包含範圍與日期；工作空間備份顯示原名稱，允許重複名稱。

Google 設定可攜帶 Client ID、選用的月曆來源、同步選項。特定工作空間匯出時，可勾選附帶 Google 連線設定；匯入時須明確選擇是否套用到本機。授權憑證、裝置識別、同步中的請求與暫存表單不匯出。

Google Calendar 的原始資料仍在 Google；備份保存來源設定，不包含月曆活動或離線快取。2026-10-10 已決定取消「備份附帶月曆離線快取」的選配構想，讓備份保持輕巧，不列為後續待實作項目。活動快取只保存在目前瀏覽器本機的 IndexedDB，不隨檔案備份、Drive 備份或跨裝置同步攜帶；新瀏覽器還原後重新連線 Google 讀取活動。

### 匯入

先解析並驗證，再顯示工作空間數、任務數、備份日期與匯入方式。格式不支援、資料損壞、日期或顏色不合法、分類／狀態參照錯誤時，不修改現有資料。

- **全部資料匯入：** 顯示「將取代目前所有工作空間與設定」警示，列出受影響數量，提供「先下載目前備份」，要求確認後才一次套用。匯入成功後，Google 自動同步先暫停，重新連線時由使用者選擇如何與既有雲端資料接續。
- **工作空間匯入：** 直接新增工作空間。重新產生工作空間及內部實體的識別碼並修正參照，避免與原資料連動；名稱重複可以保留。外部月曆的 Google 來源 ID 保留，新工作空間的綁定 ID 重新建立。
- 匯入結果通知其他分頁。既有編輯表單保留草稿；若原任務已被取代，提示另存為新任務，避免把舊內容寫回新資料。

## 4. 同一瀏覽器的分頁同步

工作空間資料先保留 localStorage，新增統一資料存取層。所有任務、分類、狀態、工作空間及設定的寫入都經過同一入口。

同步流程：

1. 每次變更取得同源寫入鎖，讀取最新資料，再套用此次操作。
2. 增加版本並完成保存；保存失敗時提示，不能顯示成已成功同步。
3. 透過 BroadcastChannel 通知其他分頁，以 `storage` 事件補強通知。
4. 接收分頁重新讀取並驗證資料，再更新畫面；不把收到的資料再次當作本機修改上傳。

Web Locks 可協調同一網站不同分頁的操作，`storage` 事件會通知同源的其他分頁。只加入事件監聽仍不足以防止兩個分頁同時以舊快照覆寫，因此寫入協調必須一起完成。[Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)、[storage 事件](https://developer.mozilla.org/en-US/docs/Web/API/Window/storage_event)

各分頁保留自己的工作空間選擇、視圖、捲動位置與未送出的表單；一個分頁切換工作空間不強迫另一個分頁跳轉。外觀偏好可同步到同一瀏覽器的分頁。

同一任務被其他分頁修改後，正在編輯的視窗提示「此任務已更新」，提供載入新版本或將草稿另存為新任務。不同任務的修改依序套用，不互相覆蓋。

月曆快取已使用獨立的 `iih-orbit-calendar-v1` IndexedDB，來源游標與最多六段日期實例快取一起保存；同帳號及來源的工作空間共用讀取。雲端待處理操作及版本紀錄將另用 IndexedDB。工作資料的寫入鎖不支援時已提供交易式儲存替代方案；Calendar 的 GET 讀取在支援 Web Locks 時協調同一來源，其他環境仍能重讀共享快取。

分頁同步限同一網站來源與瀏覽器使用者設定檔；不同瀏覽器或不同電腦透過 Drive 同步。

## 5. Google Calendar 的資料與畫面

### 來源管理

設定頁連線 Google 後列出可讀取的月曆，讓使用者勾選並指定顯示在哪些工作空間。同一來源可出現在多個工作空間，共用一次讀取的快取。

左側新增「外部月曆」群組，以月曆名稱、來源顏色及唯讀標記區分，例如「Google・學程行事曆」。可切換顯示、設定本機顯示顏色與解除綁定；月曆改名不建立新的任務分類。

### 活動行為

- 在月曆與週視圖疊加顯示；一般任務清單、看板、完成比例、待辦與逾期數量維持本機任務的語意。
- 點選活動開啟唯讀明細，提供「在 Google Calendar 開啟」。第一版不提供拖曳改期、編輯、完成狀態或刪除 Google 活動。
- 來源連線、Calendar ID 與 Event ID 組成識別；重複活動保留系列及例外資訊，重新讀取不產生副本。
- 正確處理活動修改、取消、重複活動例外、時區與跨日區段。Google 的結束時間不包含該時間點，全天活動也依此換算，避免多顯示一天。[Events 資料格式](https://developers.google.com/workspace/calendar/api/v3/reference/events)
- 沿用目前週視圖規則：有時間的跨日活動，完整覆蓋的日期放全天區，首末日不足一天的區段放時間格線。
- 離線時保留快取並顯示最後更新時間；移除來源只移除外部活動顯示，不刪除本機任務。

### 讀取同步

初次載入與重新整理必須處理所有分頁資料。第一個里程碑先依目前檢視日期及前後緩衝區定期重新讀取，確保重複活動與取消事件正確，再完成增量同步。

增量同步保存每個來源自己的同步游標。來源層保存一般活動、重複活動系列與例外，不加日期篩選；顯示層另按日期範圍取得 Google 展開的活動實例。來源更新後重新讀取受影響的顯示範圍，不能把同步游標與不相容的日期篩選混用。游標失效時只重建該來源的快取，不清空工作空間。這兩個里程碑都屬於 Calendar 階段的驗收範圍。[Calendar 增量同步](https://developers.google.com/workspace/calendar/api/guides/sync)、[Events.list 參數限制](https://developers.google.com/workspace/calendar/api/v3/reference/events/list)

預設每 5 分鐘更新，可選手動、1／5／15 分鐘；回到頁面時檢查是否需要更新。無後端版本使用定期讀取；Google 的推播通知需要可接收請求的 HTTPS 伺服器。[Calendar 推播需求](https://developers.google.com/workspace/calendar/api/guides/push)

## 6. Google Drive 備份與同步

### 檔案與權限

採用 Google Drive API v3，在「我的雲端硬碟」建立可見的 `IIH Orbit` 資料夾，以 `drive.file` 權限管理程式建立或使用者明確授權的檔案。首版的雲端匯入清單只列出程式可存取的 Orbit 備份；其他 JSON 檔可先下載，再從本機匯入。若未來要直接選取任意 Drive 檔案，再加入 Google Picker。[Drive 權限說明](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)

每次保存建立新的版本檔，包含資料集識別、同步範圍、版本識別、來源版本及內容校驗資訊。檔名方便閱讀，辨認版本使用識別資料，不依賴名稱或電腦時間。

### 備份操作

提供「立即備份」「查看雲端版本」「下載」「還原」。可備份全部或選定工作空間；手動還原遵守本機匯入規則：全部取代須警示，工作空間備份新增副本。

自動備份及同步資料每份保留最新內容加過去七份，共八份；讀取及保存後自動清理過舊版本，移至 Drive 垃圾桶，保留原內容及父版本中繼資料。手動另存不套用上限。衝突未解決、未完成上傳的集合暫不清理，本機基準及佇列所需版本暫時保留。每份刪除前重新校驗雲端內容及保留規則；清理失敗獨立提示，不將已保存內容或可讀清單當成失敗，下次讀取再重試。

1.6.0 將雲端列表按集合分組，以範圍名稱、最近保存時間及摘要辨識，過去備份只顯示日期時間並預設收合。Drive 內最新同步版本放在「同步資料」，手動、自動及舊同步版本分別放在「歷史備份」的對應子資料夾；更新時整理該集合，既有檔案提供整理入口。整理只調整檔名、摘要索引與父資料夾，檔案識別碼、JSON 及版本關係保留，未解決的分支同時呈現；整理失敗可獨立重試。

1.6.0 加入使用者確認的雲端刪除：立即備份產生的獨立檔案可逐份移至垃圾桶；自動備份／同步資料的過去備份也可逐份移至垃圾桶，保留原 JSON 與父版本中繼資料以維持跨裝置連續性；清單隱藏已刪除備份，整理不搬回。多份最新內容待選擇時可明確確認刪除其中一份，唯一最新內容則需整份刪除。刪除整份資料包含全部分支與歷史，先列出範圍，再按一次確認；不要求輸入文字。目前集合先停止本機自動處理、解除連結及取消其待上傳版本。刪除標記及缺失基準檢查避免更新後的其他客戶端重新上傳舊集合；失敗可重新確認剩餘檔案繼續，其他資料集與本機工作資料保留。

Drive 操作順序為「連線 → 讀取所有雲端資料 → 查看並使用；確定沒有資料才建立」。目前使用的資料也列在同一清單，不能因沒有其他資料而顯示空清單。讀取中、失敗及確認空清單分開呈現；舊清單保留並標示尚未確認，成功讀取前不換用或新建。只有本機舊連結時先檢查雲端，缺失就提供清除入口。建立第一份前再次檢查是否有其他裝置新增資料；已有資料另建僅放在次要選項。預設保存全部工作空間與設定並接收其他裝置更新；範圍與備份方式、頻率及檔案整理收合。選用流程直接顯示預覽，列出覆蓋範圍後按一次確認，日常用語不顯示集合／分支／本機基準。暫停、恢復及同範圍切換模式沿用資料集，更換範圍才另建並說明舊資料保留。

### 自動同步

備份與同步要分開提供：備份只保存；同步還會讀取另一台電腦的新版本並更新本機。

- 使用者主動啟用，選擇「全部工作空間」或勾選特定工作空間。每個同步集合具有獨立識別，改變集合時建立新的同步設定。
- 初次設定預設跨裝置同步，啟用期間的暫停狀態不覆寫表單選擇。完整範圍同步主題、主題色、提醒、月曆來源顯示與月曆更新頻率；部分範圍不包含全域外觀及提醒。字級、帳號、授權、Client ID 與 Drive 模式、範圍及儲存頻率保留在各裝置。
- 雲端版本格式 3 的同步摘要涵蓋共享設定並排除字級；格式 1／2 的校驗維持原計算。舊基準讀取一次便轉成新的同步摘要，既有檔案不改寫，實際修改追加新版。索引使用現有摘要欄位的格式前綴，不增加私有屬性數；舊程式讀取新版會拒絕，跨裝置須使用更新後的程式。
- 第二台電腦連線後先讀取「雲端資料」，按「查看並使用」，預覽確認後接續；不直接把空白本機資料推上去覆蓋。
- 已連結的資料出現同步分歧時，只有一份可選雲端內容就直接套用；多份則展開副本清單，選定後立即套用，不再增加預覽確認。其他副本保留為過去備份，套用期間本機、雲端或連線變更時拒絕舊操作；日常更新按鈕稱為「立即同步」。
- 修改後預設等 15 秒合併保存；每 5 分鐘檢查遠端更新，可手動同步。待保存的修改持久化，離線操作在恢復網路與授權後續傳。
- 本機沒有尚未同步的修改，且遠端為目前版本的後續版本時，套用遠端資料並通知其他分頁。
- 本機與遠端從同一版本各自修改時，以最近唯一共同祖先比較變動，自動整併不同欄位、任務與子任務。新的版本連接各份來源，已完成的檔案不覆寫；同時上傳最多重試三輪整併，不使用檔案鎖。
- 任務衝突納入最新工作資料與備份，右側欄列出全部工作空間的待選任務，讓使用者比較並選用，選擇可復原與重做。其他任務繼續同步；已選用紀錄仍保存，兩台裝置選了不同版本則再次待選。
- 設定或結構分歧、缺少可靠基準時，衝突面板提供「使用這台電腦的內容」「使用這份雲端資料」「加入工作空間」。有基準時選定內容只決定衝突部分，其餘安全修改一起整併；無法安全判斷時使用選定完整內容。完成選擇前不丟棄任何版本。
- 遠端套用不觸發再次上傳；相同內容不重複建立版本；同一瀏覽器只由一個具有效授權的分頁執行雲端工作。

自動同步包含工作空間資料與月曆來源綁定；完整範圍另包含主題、主題色、提醒與月曆顯示設定，部分工作空間保留全域設定。字級、Client ID、帳號、授權與 Drive 同步排程維持各裝置設定。外部月曆快取可重新取得，不加入每次自動上傳。

兩台電腦同時保存也採用各自新增版本檔，避免覆寫同一個唯一備份。版本關係與分支偵測要實作並測試，不能只比較「最後修改時間」。

## 7. Google Cloud Console 設定

使用者首次設定步驟：

1. 建立或選擇自己的 Google Cloud 專案。
2. 啟用 **Google Calendar API** 與 **Google Drive API**，都是使用 v3；不需要另申請名為「Drive 同步 API」的服務。[Calendar 官方入門](https://developers.google.com/workspace/calendar/api/quickstart/js)、[Drive 官方入門](https://developers.google.com/workspace/drive/api/quickstart/js)
3. 設定 Google Auth Platform 的應用名稱、使用者範圍與授權權限；使用測試模式時加入自己的測試帳號。
4. 建立 OAuth 用戶端，類型選擇「網頁應用程式」，設定授權的 JavaScript 來源。
5. 將 **OAuth Client ID** 貼進 Orbit 設定頁，分別啟用 Calendar 與 Drive，按需取得授權。

第一版採用 Google Identity Services 加直接 REST 呼叫，這個設計只要求 Client ID；不要求 API Key 或 Client Secret。Calendar 初版使用 `calendar.readonly`，Drive 使用 `drive.file`，只啟用 Calendar 時不請求 Drive 權限。[瀏覽器授權模型](https://developers.google.com/identity/oauth2/web/guides/use-token-model)

本機 Google 授權測試建議固定使用 `http://localhost:4200`，依官方指引加入 `http://localhost` 與含連接埠的來源。目前程式使用 `http://127.0.0.1:4200`，兩者的本機儲存互不共用；若改位址，必須先完成檔案備份，再在新位址匯入，不能讓使用者以為原資料消失。[授權來源設定](https://developers.google.com/identity/oauth2/web/guides/get-google-api-clientid)

正式站台為 `https://chiyang.github.io/iih-orbit/`。每位使用者自行申請 Google OAuth Client ID，將 `https://chiyang.github.io` 加入已授權 JavaScript 來源；設定頁以此正式來源提供教學，另顯示目前開啟的來源供本機測試。Client ID 不預先寫入程式或 GitHub workflow，匯入後仍須確定使用位址已在該 Cloud 專案登記。不同電腦建議沿用同一 Cloud 專案及授權設定；更換專案後，既有 Drive 檔案的可存取範圍需重新確認。

### GitHub Pages 與 origin 限制

Client ID 是瀏覽器授權流程使用的公開識別，不必當成密碼隱藏。Authorized JavaScript origins 限制授權請求可從哪些網站發起，不會讓已放進前端的 Client Secret 變得保密。

本專案儲存庫為 `https://github.com/chiyang/iih-orbit.git`，GitHub Pages 部署網址為 `https://chiyang.github.io/iih-orbit/`，授權來源填 `https://chiyang.github.io`，不含 `/iih-orbit/`。同一帳號網域底下的其他專案也屬於同一 origin；若要隔離這個工具，可考慮專用的自訂網域。這是依 origin 不包含路徑的規則做出的部署建議。[Google origin 規則](https://developers.google.com/identity/protocols/oauth2/javascript-implicit-flow#javascript-origin-validation-rules)

Origin 限制不會把 Access Token 綁定到該網站；Google API 的 Access Token 仍是 Bearer Token，取得它的人可能在有效期內使用。使用者選擇在 localStorage 保存未過期憑證，支援關閉網頁後重開與斷網重連；這個儲存仍可被同源 JavaScript 讀取。程式按需取得最小權限、不將憑證寫入工作資料或備份，並避免把活動描述當成可執行 HTML。[Google 憑證保護說明](https://developers.google.com/identity/protocols/oauth2/resources/best-practices)

分頁連線以 Client ID、帳號、資料世代及公開失效識別檢查；同來源新分頁驗證 localStorage 的有效憑證，也可透過 BroadcastChannel 接續其他分頁。解除連線或重新授權更新不含憑證的公開失效識別，避免未收到通知、延遲回覆或恢復舊分頁時復活舊授權；舊分頁不能清掉新的共用憑證。重置及全部匯入改變世代，舊憑證拒絕恢復。有效的舊 sessionStorage 憑證驗證後遷移，localStorage 保存不延長 Google 的原期限。[localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)、[BroadcastChannel](https://developer.mozilla.org/en-US/docs/Web/API/Broadcast_Channel_API)

若未來改用需伺服器交換授權碼與管理更新憑證的 Code Model，須另規劃伺服器端元件；GitHub Pages 的靜態前端不能替代該元件。[Google Code Model](https://developers.google.com/identity/oauth2/web/guides/use-code-model)

### 無後端的自動同步邊界

程式開啟、網路可用、Google 授權有效時可以自動同步。所有分頁關閉後不會繼續執行；背景分頁更新也可能延後。Access Token 過期後顯示「需要重新授權」，由使用者點擊再取得，期間繼續保留本機修改。[Google Token 到期說明](https://developers.google.com/identity/oauth2/web/guides/use-token-model)

因此本版提供的是「使用期間的自動同步」。若未來要求關閉程式後仍能持續同步，需另規劃常駐桌面程式或後端。

### 重置規則

- 「清空工作資料」刪除工作空間與月曆快取，保留外觀與公開連線設定，建立一個空白工作空間。
- 「重置整個 Orbit」清除 Orbit 舊版升級來源、備份及偏好鍵，保留一份新世代的空白狀態記錄，避免重載範例；不使用 `localStorage.clear()` 影響同一來源其他程式。月曆快取另行清空；不含工作資料的寫入協調鎖保持可用，未來雲端佇列加入時也需清理。
- 重置前提供下載備份，要求明確確認，暫停同步並通知其他分頁。重置後不重新載入範例任務或偷偷還原舊版鍵。
- 本機重置不刪除 Google Calendar 原始活動或 Drive 備份。重置後建立新的資料世代，雲端資料需手動選擇恢復或接續，避免自動同步立刻把資料帶回。
- 「解除本機連線」停止同來源分頁的同步及清除記憶體／localStorage 的有效憑證與舊版分頁副本；另提供前往 Google 管理應用存取權的連結，清楚區分本機停用與 Google 端撤銷授權。
