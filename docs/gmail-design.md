# Gmail 郵件與右側欄（1.7.0）

[文件索引](README.md) · [Google 連線設定](google-setup.md) · [使用指南](user-guide.md)

本版依已確認的規劃實作，維持純前端；WebMCP、AI 摘要、日期判讀與雙向同步均未列入本版。後續依使用者需求加入按需讀取的郵件內文預覽與全體任務的 Markdown 描述。

## 畫面

### 側欄與訊息提醒

右上角 Gmail 和鈴鐺開啟共用右側欄，欄內可切換 Gmail／訊息提醒；切換鈕採共用底框的分段選擇樣式，選取分頁以底色及輕微陰影標示，保留懸停與鍵盤焦點反饋。頁首 Gmail 入口僅顯示信封圖示與滑鼠提示。中間保留看板、清單、月曆、週視圖，切換視圖不關閉側欄。桌面側欄與工作區並排，各自捲動；側欄可拖曳分隔線或使用方向鍵調整為 300–520px，寬度保存在目前瀏覽器。較窄的桌面視窗會將左側導覽收合為選單，保留郵件與工作區並排。700px 以下使用右側抽屜，支援焦點限制、Escape 關閉與按鈕建立任務。

訊息提醒原有日期清單、來源篩選、月曆多選和提醒設定保留，範圍按鈕改為換行。即將開始的短暫右下角提示仍依使用者設定顯示；它與供瀏覽的訊息提醒是不同用途。

### 設定與標籤

Gmail、Calendar、Drive 共用的 Client ID 與首次說明集中於「設定 → Google 連線」分頁，依需要載入；該頁保留個別及一次全部授權。已有 Client ID 時，各服務設定分頁亦提供連線、切換帳號及解除連線；沒有 Client ID 才顯示「前往 Google 連線設定」。Drive 功能分頁稱為「遠端同步備份」。三個服務分頁共用連線區，統一標題、連線狀態、帳號及操作按鈕。

Gmail 設定頁說明手動更新與快取規則，本版不新增定時輪詢或更新頻率選項。郵件側欄頂部僅保留更新按鈕；沒有有效連線時顯示開啟 Google 連線設定的按鈕。搜尋與標籤篩選保留，移除常駐的搜尋語法及拖放說明，將這些說明移到設定。

標籤使用可收合的展開區：標頭始終顯示已選標籤，展開後先列出按名稱排序的自訂標籤，再按收件匣、未讀、星號、重要、寄件備份、草稿、分類、垃圾郵件及垃圾桶列出系統標籤，可逐項點亮。多選採「符合任一已選標籤」；「只看收件匣」選取 INBOX，「所有郵件」取消標籤選取，兩者同樣須按「套用篩選」才重新篩選。所有郵件預設不含垃圾郵件與垃圾桶，需要時可另外選取這兩個標籤。Gmail 標籤不會自動變成 Orbit 分類。

標籤選取只修改側欄草稿，標頭以「未套用」標示，郵件清單、展開的回覆及既有讀取維持目前已套用的篩選。選好後按「套用篩選」一次提交最終標籤聯集並收合選單，按「取消變更」恢復已套用標籤；選回相同組合不送出請求。搜尋、更新及載入更多只使用已套用的標籤，不會偷偷套用草稿。只保存已套用標籤；未套用選擇不進 localStorage，重開側欄或帳號／連線／資料世代變更時恢復已套用選擇。

### 郵件列表、討論串與搜尋

每個討論串在列表只呈現一張卡片，以真正的首封郵件作為主旨、寄件人、預覽與建立任務來源。搜尋或標籤只命中後續回覆時，以最小討論串索引找出首封，再取得首封預覽，顯示整串封數；其他討論串接續排列，維持依最新符合篩選郵件的順序。追加分頁不會用回覆替換首封。按封數按鈕，在首封下方以縮排與連接線展開其他郵件，回覆按時間排序，每封都可預覽、拖曳或建立任務；不重複呈現首封。

初始清單只讀取討論串識別碼、日期與標籤索引，保留真正首封及封數；完整各封預覽在展開或開啟郵件預覽時才讀取。每封郵件顯示寄件名稱、完整寄件地址、主旨、收信日期、Gmail 原文預覽、標籤，以及「在 Gmail 開啟」「建立任務」。清單預覽來自 Gmail `snippet`，不經 AI。點擊主旨或預覽文字，在較寬的視窗按需讀取內文；顯示寄件地址、收件人／副本、日期、HTML 的可讀文字／連結／表格或純文字，以及附件名稱。視窗可建立 Orbit 任務並保留原信連結。寄件地址只是供使用者檢視，不宣稱完成寄件人真偽驗證。

搜尋支援 Gmail `q` 語法，作用於目前標籤聯集；游標和本機預覽按搜尋詞隔離，切換搜尋不沿用舊游標。列表依 `threadId` 分組，整串任一封含 `UNREAD` 即視為有未讀郵件。寄件人與主旨略為放大。卡片右側用實心圓表示未讀、空心圓表示已讀，搭配未讀主旨粗體及滑鼠／輔助閱讀提示；不重複加入已讀／未讀文字標籤。開啟郵件預覽時直接顯示左側討論串選擇區，使用完整可用高度，首封在前，後續回覆按時間排列；右側內文獨立捲動，選信後從上方閱讀。討論串可收合與重新展開，保留選取；700px 以下改為上下排列。更新討論串讀取 `threads.get` 的信件資訊，逐封選取時才讀取本文。建立任務以選定的信為準，不修改任何已讀狀態。[Google 搜尋說明](https://developers.google.com/workspace/gmail/api/guides/filtering)、[Google 討論串說明](https://developers.google.com/workspace/gmail/api/guides/threads)

### 內文預覽

內文優先使用 HTML，沒有可用 HTML 時使用純文字，處理巢狀 MIME、base64url 與字元集。只讀取選定信件的內文，必要時讀取分離的文字 MIME body，不下載檔案附件。可預覽內文上限為 512 KiB，過大、編碼損壞或沒有文字時保留 snippet，提示使用者到 Gmail 查看。讀取失敗可重試，沒有授權或離線時仍有原信入口。

HTML 經 DOMPurify 的被動內容允許清單清理，移除腳本、表單、嵌入內容、CSS、圖片和資源屬性；連結只允許 HTTP／HTTPS／mailto，另由 Angular 清理顯示內容。外部連結使用新分頁與 `noopener noreferrer`。HTML 排版表格去除空白欄並攤平為文字區塊，避免巢狀格線與提早換行；有表格標頭／標題的資料表保留。Markdown 任務表格維持原樣。不自動載入追蹤圖片，完整圖文與附件在 Gmail 查看。讀取不回寫 Gmail、不改未讀標籤。

## 建立任務

| 放下的位置 | 建立結果 |
| --- | --- |
| 看板狀態欄 | 對應狀態、無日期任務 |
| 清單 | 一般待完成任務，無日期 |
| 月曆日期 | 該日全天任務 |
| 週視圖全天區 | 該日全天任務 |
| 週視圖時段 | 每 15 分鐘對齊開始位置，預設一小時，跨午夜換日 |

拖放直接建立，不判讀郵件內日期。標題取主旨，描述帶入寄件人及地址、收信時間、主旨、預覽和可點擊的 Markdown 原信連結，控制在 2,000 字元範圍，優先保留連結。寄件資料與預覽中的 Markdown 標記作為文字處理；一般網址仍可自動連結。沿用目前專案，預設中優先、未分類。按「建立任務」則開啟已填入內容的任務編輯表單，供觸控與鍵盤操作。預覽視窗建立任務採用目前顯示的郵件快照，列表背景更新不會使其變成空白草稿；帳號或資料世代變更時拒絕使用舊來源。

拖放後可編輯新任務或撤銷建立。撤銷使用建立時的內容基準；其他分頁或使用者已修改時拒絕刪除。只接受此分頁正在拖曳的郵件，工作空間、帳號或資料世代改變會取消拖曳，重複 drop 不建立兩份。

任務是獨立副本，原信保留、不標為已讀、不新增 Gmail 標籤。拖放建立或撤銷提示留在郵件側欄，不以底部浮窗遮住工作區；側欄開啟時也不顯示右下角提醒浮窗。使用者可再將任務移至 Calendar，Markdown 原信連結在活動描述轉為可辨識的文字網址，避免網址尖括號被當成 HTML 而消失；不追蹤同源、不合併顯示，不回寫 Gmail。

## 讀取、授權與保存

- 個別連線使用 `gmail.readonly` 與帳號識別授權，沿用既有 Google Token Model。三個服務共用保存一次的 Client ID，可分別選擇不同帳號；需在自己的 Google Cloud 專案啟用 Gmail API、設定讀取權限和測試使用者。Google 連線頁另提供「一次授權全部服務」，一次選擇同一帳號並申請 Calendar 讀取／寫入、Gmail 讀取與 Drive 檔案權限；憑證含使用者同意的合併權限，但各服務的本機連線紀錄與解除操作仍分開。只有已取得權限的服務接續，部分拒絕不阻止其他已授權服務；臨時的合併連線不額外保存憑證，既有服務憑證沿用下述保存方式。
- `messages.list` 每次取得 25 個識別碼，再以 `messages.get` 的部分欄位取得預覽及標頭。每個新出現的討論串透過 `threads.get` 的最小索引（識別碼、threadId、日期、標籤，無 snippet／payload）取得首封識別碼、整串封數與未讀狀態；首封不在該頁時，才額外讀取首封預覽。同帳號的單封預覽與首封／封數索引各保留最多 200 筆五分鐘記憶體快取，切換標籤或搜尋遇到同一封信時重用；手動更新略過快取，帳號、Client ID 或資料世代變更清理。最多四個請求同時進行；分頁重用已載入的首封。使用 `format=full` 搭配明確的 `fields`，回應排除 body、parts 和附件；避免依賴 metadata 格式對 snippet 的省略行為。[Google 郵件讀取](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/get)
- Gmail 的多個 `labelIds` 表示交集，因此每個已選標籤有獨立分頁游標，合併各游標的最新郵件、去重後呈現。未顯示的舊郵件保留供下一頁，更新失敗不破壞原游標。[Google 郵件清單](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/list)
- 開啟側欄、重新整理、回到前景、套用標籤或搜尋時，先顯示對應的快取，只有超過五分鐘或沒有快取才讀取；保留原本成功更新的時間，空郵箱同樣有有效快取。完整取得列表與首封資訊後才替換畫面、游標及本機快取，失敗不更動成功時間。沒有新篩選快取時，先保留上次列表並標示，載入成功後才切換，避免將舊列表誤當成新結果。切換到有快取的標籤／搜尋即使離線或授權到期也能瀏覽。一般讀取失敗後，三十秒內不因重開側欄或回到前景而反覆自動讀取；手動更新可重試，但仍遵守所有 Gmail 請求共用的限制冷卻。
- 手動更新重建第一頁；載入更多沿用記憶體游標。游標不寫入 localStorage，重新整理後按載入更多，先重建已顯示的列表範圍，再接續下一頁，完整成功後才更新列表。離線保留可用預覽，恢復網路後依有效授權及快取期限決定是否讀取；沒有定時輪詢。
- 本機預覽保存目前帳號最近使用的六組標籤／搜尋，每組最多前 75 封，以及這些郵件所屬討論串的首封預覽、封數與未讀狀態；不保存全討論串內容，依資料世代、Client ID、帳號、標籤及搜尋詞隔離，最久使用一天。總存檔限制一 MiB，超過時優先清理較少使用的篩選；可接續舊版單組快取。更換帳號、解除連線、重置或全部還原清理舊快取。未到期的 Gmail 憑證依要求暫存於 localStorage，重開頁面仍須驗證原期限、帳號、Client ID、權限與資料世代；有效的舊 sessionStorage 連線會遷移。解除連線、到期、重置或切換設定後不可恢復舊授權，且舊分頁不得清除較新的授權。Calendar／Drive 憑證維持 sessionStorage；Gmail 帳號、標籤選擇與預覽只存目前瀏覽器 localStorage，不進 JSON／Drive 備份；共用 Client ID 沿用公開 Google 設定的備份規則，已建立任務則照常備份。
- 各封討論串預覽由清單與內文視窗共用五分鐘記憶體快取，同時讀取合併為同一請求；收合／重新展開或重開視窗時可重用，手動更新重新取得。最多八串、合計 400 封預覽，較大的單串仍可讀取但不加入此快取；不保存本文，不寫入 localStorage／IndexedDB 或備份。帳號、Client ID、連線版本或資料世代變更立即隔離並清除，標籤／搜尋切換清除清單展開狀態。
- 按「套用篩選」或送出搜尋後更新目前篩選，取消舊清單的進行中與排隊請求，等待 400 毫秒開始新批次；單純逐項選標籤不取消既有讀取、不發出新請求。停止後續郵件／討論串讀取，遲到回覆不能覆蓋新篩選。清單取消不打斷同帳號正在閱讀的內文或討論串。Gmail 清單、巢狀標籤分頁、討論串及內文共用最多四個進行中讀取；批次失敗停止其他工作，保留原始錯誤原因。
- 403 依 Google 回傳的原因區分頻率限制、每日配額、管理員政策及權限。頻率限制（403／429）與暫時性伺服器錯誤最多重試兩次，從至少一秒開始逐次退避，共用等待時間並採用短期 Retry-After；超過十秒的提示直接返回錯誤，供使用者稍後更新，不提前自動重試。重試耗盡或遇到長期 Retry-After 後，所有列表、討論串及內文讀取共用冷卻：頻率限制至少六十秒，伺服器錯誤至少三十秒，Google 指定更久就等到指定時間；期間新的讀取直接提示，不送網路請求。冷卻按帳號、Client ID 與資料世代隔離，相同帳號重新授權不提前取消等待。權限、每日配額及過期憑證不重試；錯誤後釋放載入狀態，已有郵件與游標保留。參考 [Google Gmail API 錯誤處理](https://developers.google.com/workspace/gmail/api/guides/handle-errors)。
- 完整內文最多八份，只留在目前分頁記憶體，五分鐘內可重用；切換標籤保留同帳號快取，帳號、Client ID、連線版本或資料世代變更清理。舊讀取不得發布到新帳號視窗；關閉視窗不顯示遲到回覆。內文不寫入 localStorage／IndexedDB，也不進備份；任務建立仍使用精簡描述。
- 原信連結先指定來源帳號，再以 RFC Message-ID 在 Gmail 搜尋該信，不使用固定 `/u/0` 或假設 API ID 等於網頁 ID。搜尋結果可點入全文；Message-ID 缺失或過長時退回主旨搜尋，可能有多個結果。瀏覽器未登入來源帳號時由 Google 要求登入／選擇帳號。[Google 支援的搜尋語法](https://developers.google.com/workspace/gmail/api/guides/filtering)

## 全體任務的描述編輯

任務描述沿用原本的字串欄位，不增加資料格式版本，也不轉寫舊資料。使用 [Marked](https://marked.js.org/) 顯示 Markdown，輸出經 [DOMPurify](https://github.com/cure53/DOMPurify) 與 Angular 清理。支援標題、粗體、清單、勾選、表格及可點擊的連結；純文字的換行與一般網址仍可閱讀。描述中的 HTML 片段視為文字，圖片語法顯示為圖片連結，避免自動載入外部資源。看板卡片呈現文字摘要，卡片內不嵌入可點擊連結，完整描述在任務視窗閱讀。

新任務預設編輯，既有任務預設預覽。可切換模式，使用粗體／標題／清單／連結的格式按鈕；表單描述上限由 2,000 增至 20,000 字元。專注編輯將視窗放大至最多 1,100px，描述區隨視窗高度擴大，暫時隱藏名稱、分類、時程、子任務和儲存列；這些欄位的草稿保留。按「完成描述編輯」「返回完整任務」或 Escape 返回表單後再儲存。Escape 第二次才關閉任務視窗。完成描述編輯後，焦點回到編輯器的返回按鈕。

郵件自動產生的任務描述仍最多 2,000 字元，保留寄件資料、snippet 和具名稱的 Markdown 原信連結；不以較完整的內文替換已確認的輕巧快照行為。

## 驗收邊界

本機模擬驗證資料解析、分頁聯集、競態、帳號隔離、授權失效、任務建立及撤銷；實際瀏覽器檢查側欄、各視圖與手機抽屜的排版和操作。依使用者指示，真實 Google 授權、信件資料、原信帳號導向與拖曳驗收由使用者手動進行，不以模擬測試宣稱真實服務通過。
