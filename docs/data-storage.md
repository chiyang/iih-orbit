# 資料儲存與相容性

[文件索引](README.md) · [專案首頁](../README.md)

Orbit 是瀏覽器端的單人任務管理工具，沒有自建後端。核心工作資料仍保存在 localStorage，IndexedDB 用於活動快取、待上傳資料與寫入協調。

## 儲存位置

| 內容 | 位置 | 備份規則 |
| --- | --- | --- |
| 工作空間、專案、任務、分類、狀態、順序、外觀、提醒及公開 Google／Drive 偏好 | localStorage：`orbit-workspaces-v2` | 依全部／選定範圍匯出 |
| 當前工作空間 | 每個分頁的 sessionStorage：`orbit-active-workspace-v1` | 不匯出 |
| 視圖、日期、篩選、排序、來源開關、捲動與右側欄 | localStorage：`iih-orbit-browse-state-v1` | 不匯出 |
| Calendar 活動、來源版本與同步游標 | IndexedDB：`iih-orbit-calendar-v1` | 不匯出／同步 |
| Calendar 未過期憑證 | sessionStorage：`iih-orbit-google-session-v1` | 不匯出 |
| Gmail 未過期憑證 | localStorage：`iih-orbit-gmail-session-v1` | 不匯出 |
| Gmail 偏好與郵件預覽 | localStorage；整串預覽及本文暫存於分頁記憶體 | 不匯出 |
| Drive 未過期憑證 | sessionStorage：`iih-orbit-drive-session-v1` | 不匯出 |
| Drive 待上傳 JSON、固定檔案 ID 與同步基準 | IndexedDB：`iih-orbit-drive-v1` | 不匯出 |
| 不支援 Web Locks 時的工作資料寫入協調 | 獨立 IndexedDB 交易 | 只保存協調資料，不是任務副本 |

Gmail 快取上限、期限與限流規則見 [Gmail 設計](gmail-design.md)。所有憑證啟動時檢查帳號、Client ID、資料世代、權限與原到期時間；不延長期限。另有不含憑證的失效識別，讓未收到即時通知的分頁也拒絕舊連線。

## 工作資料的跨分頁寫入

`orbit-workspaces-v2` 外層保存資料世代與修訂識別。每次寫入先取得同來源鎖，重讀最新資料，再套用此次變更，避免以整份舊快照蓋掉其他修改。優先使用 Web Locks，不支援時以 IndexedDB 交易協調。

更新透過 BroadcastChannel、`storage` 事件與分頁取得焦點時重讀通知。各分頁選擇的工作空間獨立，切換不影響其他分頁；編輯表單保留原版本，外部更新、刪除或重置時阻止舊草稿覆蓋新內容。

同來源須有相同協定、主機與連接埠，並使用同一瀏覽器設定檔。`localhost`、`127.0.0.1`、不同連接埠與正式站台的儲存各自獨立。

## Calendar 同步協調

同一來源、Client ID、帳號及資料世代的分頁共用活動快取與同步作業鎖。切換分頁、定期檢查或收到同步完成通知時，先安靜讀取本機快取；只有需要向 Google 讀取才廣播「同步中」。取得鎖後再確認快取，其他分頁已完成則略過，避免同步通知互相觸發。

重新整理或離開頁面時停止本分頁請求並釋放標記，從上一頁／下一頁快取返回時再檢查。支援 Web Locks 的環境可探測遺留作業；替代協調依九十秒標記期限恢復。整次同步最多兩分鐘，逾時停止並說明原因；已下載活動與仍有效憑證保留，晚到回覆不能覆蓋新作業。

活動每個來源最多保留六段日期快取，月／週視圖共用所在月份及前後週。來源同步游標與版本也保存在 IndexedDB，快取不進任何備份；操作說明見 [Google Calendar](google-calendar.md)。

## Drive 待上傳與版本關係

同來源分頁共用 Drive 作業鎖、處理中狀態及列表更新通知。待上傳 JSON 與固定檔案 ID 保存於 IndexedDB，重新整理後可重試；回覆遺失時驗證同一檔案，不另建重複版本。離線修改仍由本機保存，恢復網路／授權後再處理。

單份備份上限 20 MB；小檔使用 multipart，大於 5 MB 使用 resumable。中斷留下的空檔只補完同一待上傳版本，已完成版本不改寫。版本保存父版本與內容校驗，以祖先關係判斷分歧，不依電腦時鐘；移至垃圾桶的歷史仍保留必要關係。參考 [Drive 上傳說明](https://developers.google.com/workspace/drive/api/guides/manage-uploads)。

自動備份追蹤全部可匯出內容；跨裝置同步追蹤共享內容與設定，排除各裝置的 Client ID、帳號與 Drive 控制偏好。匯出時間、程式版本或瀏覽選擇不造成重複上傳。保留八份與衝突處理見 [備份與同步](backup-and-sync.md)。

## 舊資料升級與備份格式

- 先讀取 v1 工作空間或更早的看板，第一次實際修改才寫入 v2。舊儲存鍵保留作為升級前來源，不要同時以舊版程式操作同一份資料。
- `orbit-board-v1` 的版本 1／2 升級至第一個「我的工作空間」與看板格式 4，保留任務、分類、日期、子任務與順序，加入預設封存狀態。版本 1 未提供的開始日期／時間維持空白。
- 舊版單一專案名稱轉為第一個專案，原任務歸入；既有未指定任務保留。匯入工作空間副本時重建專案識別與參照。
- 舊 `orbit-text-size-v1` 外觀偏好自動讀取；「小 90%」改稱「中 90%」但保留原比例。舊備份缺少的主題設定補為淺色與綠色。
- 備份為 `application: iih-orbit`、`formatVersion: 5`，目前應用程式版本見 [package.json](../package.json)。支援讀取格式 1–4，新備份須用支援格式 5 的版本還原。

匯入只接受已支援的欄位，驗證日期、顏色及實體參照，單檔上限 20 MB。全部匯入取代資料與設定並建立新世代；其他分頁更新畫面，但保留未送出的任務草稿。工作空間匯入建立獨立副本及月曆綁定參照，保留本機外觀；公開 Google 設定須另勾選才套用。

沒有可讀取或升級的資料時，首次狀態是空白工作空間，不自動載入範例；示範任務只在使用者建立樣板時選擇加入。首次流程見 [使用指南](user-guide.md)。

## 保存失敗與重置

一般操作無法寫入時，變更留在目前分頁記憶體，顯示提示並可立即匯出；不顯示為已保存。匯入必須成功寫入才套用，驗證或容量失敗保留原資料。未保存的分頁收到外部更新時，提示先匯出，避免靜默丟棄。

設定提供兩種重置：

| 操作 | 保留內容 |
| --- | --- |
| 清空工作資料 | 外觀、Client ID 與更新設定 |
| 重置整個 Orbit | 回到預設設定 |

兩者均清空工作內容、月曆綁定／快取及本機 Drive 狀態，停止 Google 讀取與自動處理。先提供下載全部備份，要求輸入確認文字並檢查期間是否有其他分頁更新；保存失敗不重置。

成功後移除 Orbit 舊資料與偏好鍵，保留新的空白狀態，避免重新載入舊任務；同來源其他程式的鍵不清除。寫入協調 IndexedDB 維持可用，舊世代未完成的請求不能寫回。Google Calendar 原活動及 Drive 雲端檔案保留。

清除瀏覽器網站資料也會移除本機任務與快取，操作前請先下載備份。
