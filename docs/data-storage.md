# 資料儲存與相容性

[文件索引](README.md) · [專案首頁](../README.md)

Orbit 是瀏覽器端的單人任務管理工具，沒有自建後端。核心工作資料按紀錄保存在 IndexedDB，活動快取與待上傳資料也使用 IndexedDB；localStorage 保存小型修訂通知、瀏覽偏好及服務憑證。

Gmail 快取上限、期限與限流規則見 [Gmail 設計](gmail-design.md)。Calendar、Gmail、Drive 備份及檔案瀏覽連線在目前瀏覽器保存未過期憑證，關閉後重開仍可接續；文件建立憑證只留本次分頁。有效的舊版 sessionStorage 憑證驗證後遷移。啟動時檢查帳號、Client ID、資料世代、權限與原到期時間，不延長期限；離線或請求逾時不清除憑證。另有不含憑證的失效識別，讓未收到即時通知的分頁也拒絕舊連線；舊分頁不得清掉其他分頁重新授權的新憑證。

登出目的地保存在主資料記錄的本機 `cloudResume.datasetId`，Client ID 仍在 Google 設定。這個目的地不匯出、不同步。同步並登出先讀回驗證完整雲端備份，再以當時版本與資料世代檢查原子重置；若期間有其他寫入則拒絕清除。登出後清理 Orbit 的 localStorage／sessionStorage 記錄（保留重置後的主資料）、Calendar 與 Drive IndexedDB 快取及服務憑證，其他應用程式的儲存鍵不變。

## 工作資料的跨分頁寫入

`iih-orbit-workspaces-v1` 按工作空間索引、任務、專案、分類及狀態等保存紀錄。每次寫入以同一個原生交易重讀最新資料、檢查版本、驗證並寫入變動紀錄，避免整份舊快照蓋掉其他修改。`orbit-workspaces-v2` 只保存小型世代及修訂通知；舊 localStorage 資料先驗證、交易成功後才升級通知。載入期間引導與 Google 服務等待核心資料完成。具體結構、升級限制及效能界線見 [本機紀錄與雲端分塊備份](storage-sync-upgrade.md)。

更新透過 BroadcastChannel、`storage` 事件與分頁取得焦點時重讀通知。各分頁選擇的工作空間獨立，切換不影響其他分頁；編輯表單保留原版本，外部更新、刪除或重置時阻止舊草稿覆蓋新內容。

同來源須有相同協定、主機與連接埠，並使用同一瀏覽器設定檔。`localhost`、`127.0.0.1`、不同連接埠與正式站台的儲存各自獨立。

復原與重做共用最多 50 筆操作前後的工作資料快照，在同一寫入交易中重讀最新內容；復原要求工作內容與操作後快照一致，重做要求與操作前快照一致，避免覆蓋其他分頁修改。其他工作空間、縮放模式與設定不會被快照覆蓋。復原後的新修改清除該工作空間的重做路徑；失敗或未改變內容的操作不清除。資料世代改變時清除全部紀錄；單筆徹底刪除或清空垃圾桶成功後，清除該工作空間的全部復原／重做紀錄，避免透過舊操作帶回已永久清除的任務。

## Calendar 同步協調

同一來源、Client ID、帳號及資料世代的分頁共用活動快取與同步作業鎖。切換分頁、定期檢查或收到同步完成通知時，先安靜讀取本機快取；只有需要向 Google 讀取才廣播「同步中」。取得鎖後再確認快取，其他分頁已完成則略過，避免同步通知互相觸發。

重新整理或離開頁面時停止本分頁請求並釋放標記，從上一頁／下一頁快取返回時再檢查。支援 Web Locks 的環境可探測遺留作業；替代協調依九十秒標記期限恢復。整次同步最多兩分鐘，逾時停止並說明原因；已下載活動與仍有效憑證保留，晚到回覆不能覆蓋新作業。

活動每個來源最多保留六段日期快取，月／週視圖共用所在月份及前後週。來源同步游標與版本也保存在 IndexedDB，快取不進任何備份；操作說明見 [Google Calendar](google-calendar.md)。

## Drive 待上傳與版本關係

同來源分頁共用 Drive 作業鎖、處理中狀態及列表更新通知。待上傳 JSON 與固定檔案 ID 保存於 IndexedDB，重新整理後可重試；回覆遺失時驗證同一檔案，不另建重複版本。離線修改仍由本機保存，恢復網路／授權後再處理。

單份完整邏輯備份上限 20 MB。新自動同步保存版本索引與共用區塊，先校驗全部必要區塊才發布索引；手動獨立備份及舊雲端版本保留完整 JSON。每份實體檔案小於等於 5 MB 使用 multipart，大於 5 MB 使用 resumable。中斷留下的空檔只補完同一待上傳版本，已完成版本不改寫。版本保存父版本與內容校驗，以祖先關係判斷分歧，不依電腦時鐘；移至垃圾桶的歷史仍保留必要關係。另有不顯示為正式備份的小型待上傳保護索引，供其他裝置辨識正在保存的區塊；過期作業可從本機完整佇列重建。未引用區塊完整檢查後觀察 30 天，分批移至垃圾桶，依 Drive 時間判定；規則見 [備份優化紀錄](storage-sync-upgrade.md)。參考 [Drive 上傳說明](https://developers.google.com/workspace/drive/api/guides/manage-uploads)。

自動儲存固定追蹤全部工作空間的共享內容與設定，排除各裝置的 Client ID、帳號與 Drive 控制偏好。舊模式與部分範圍仍可讀取及驗證；使用或再次同步時先處理原集合，再安全轉為完整雙向同步，不改寫舊雲端 JSON。等待與檢查間隔仍可於更多操作調整。匯出時間、程式版本或瀏覽選擇不造成重複上傳。保留八份與衝突處理見 [備份與同步](backup-and-sync.md)。

跨裝置同步沿父版本關係尋找最近且唯一的共同祖先，按識別碼整併任務、子任務、專案、分類與狀態，再比較各欄位相對基準的變動。月曆來源以帳號及 Calendar ID 比對，避免不同裝置的來源識別造成假衝突；來源綁定按集合整併。引用或日期檢查失敗時不套用無效資料。同時上傳以追加版本保存，沒有跨裝置互斥鎖，最多三輪自動整併後保留分歧供重試或選擇。

IndexedDB 的 `base` 保存已確認同步基準，`mergeBase` 暫存正在整併的共同基準。讀取時校驗內容、資料集合、範圍、版本與摘要，不能以不符的快取判定修改；基準已移至垃圾桶但本機仍有有效快照時，可繼續整併。沒有可讀或可驗證的唯一基準時保留版本，不推測勝負。這些快取在解除集合、全部還原或重置時清理，不進匯出檔。

## 舊資料升級與備份格式

- 啟動時讀取及驗證 v2、v1 工作空間或更早的看板，再以交易遷入 IndexedDB；成功後 v2 鍵改為小型通知。保留舊世代、修訂及資料，不要同時以舊版分頁操作；更新後重新載入所有分頁。無 Web Locks 時升級前須關閉舊分頁。
- `orbit-board-v1` 的版本 1／2 升級至第一個「我的工作空間」與看板格式 4，保留任務、分類、日期、子任務與順序，加入預設封存狀態。版本 1 未提供的開始日期／時間維持空白。
- 任務可選欄位 `pinned`（布林）與 `updatedAt`（UTC ISO 編輯時間）隨任務保存、備份與同步。舊任務缺少欄位時保持原形，不補預設值或虛構時間，以保留既有備份內容校驗；第一次內容修改才加入時間，釘選及同欄排序不改時間。
- `orbit-device-v1` 在目前瀏覽器保存穩定身份與可填寫的裝置名稱，不納入備份或同步。新的任務內容編輯附上 `editSource: {id, name}`；版本選項的可選 `source` 保留該份原始來源與時間，避免安全欄位整併後誤用其他裝置的顯示紀錄。舊來源不補寫，來源與時間不參與內容勝負判定。
- 任務可選欄位 `deletedAt`（UTC ISO 刪除時間）表示已移至垃圾桶，完整任務仍留在工作空間與備份中；一般任務來源及提醒排除該欄位存在的項目。還原時移除標記，刪除及還原不改內容編輯時間。單筆徹底刪除與清空垃圾桶必須成功寫入才套用，保存失敗保留原內容；相關有效文件關聯標記移除，雲端原檔保留。
- 工作空間可選欄位 `taskConflicts` 保存任務識別及多份 `{key, task}` 選項；`task: null` 表示永久刪除選項，`resolved` 指向已選用的 key。待選及已選用紀錄都納入備份與同步；已選用快照用於辨識舊分歧，後續任務編輯保存在主任務內容中。舊資料沒有此欄位時不補欄位，保留既有校驗。匯入工作空間副本時一併重建任務與子任務識別、選項 key 及選擇參照。相同集合的裝置需更新至支援此欄位的程式。
- 並排編輯器以原版本 key 記錄採用決定，另將修改後的完整任務一次保存到主資料。過期衝突、工作空間取代、無效引用或時程會拒絕保存；已處理選項保留，之後的整併不以新草稿改寫這些快照。未處理記錄的暫時主卡片不被列為另一份版本，避免同步時累加共同內容。
- 工作空間可選欄位 `headerCompact`（布林）表示資訊區縮小或展開，納入工作空間備份、匯入副本與 Drive 同步校驗。舊資料缺少時不補欄位，保留既有校驗；舊本機精簡模式可升級寫入，只有同步欄位仍缺少時才套用，避免蓋掉其他分頁已保存的模式。
- 舊版單一專案名稱轉為第一個專案，原任務歸入；既有未指定任務保留。匯入工作空間副本時重建專案識別與參照。
- 舊 `orbit-text-size-v1` 外觀偏好自動讀取；「小 90%」改稱「中 90%」但保留原比例。舊本機外觀記錄缺少的主題設定補為淺色與綠色；匯入備份時深淺色保留本機選擇，缺少主題色則使用原本的綠色。
- 深淺色／跟隨系統與字體大小不再加入新備份，舊備份的這些偏好仍可讀取及驗證，但匯入或同步時不套用。Drive 雲端格式 4 的同步摘要排除主題與字級，格式 1／2／3 的原始校驗保持相容；舊本機基準讀取一次後升級，不改寫既有雲端檔案。新自動同步使用雲端格式 5 的區塊索引，沿用格式 4 的共享摘要規則；跨裝置須使用可讀雲端格式 5 的更新版本。
- 備份為 `application: iih-orbit`：基本資料格式 5，含文件關聯格式 6，含連結用途／順序格式 7；支援讀取格式 1–6 的舊備份。目前應用程式版本見 [package.json](../package.json)，各裝置須支援所使用的資料格式。

匯入只接受已支援的欄位，驗證日期、顏色及實體參照，單檔上限 20 MB。全部匯入取代資料與設定並建立新世代；其他分頁更新畫面，但保留未送出的任務草稿。工作空間匯入建立獨立副本及月曆綁定參照，保留本機外觀；公開 Google 設定須另勾選才套用。

沒有可讀取或升級的資料時，首次狀態是空白工作空間，不自動載入範例；示範任務只在使用者建立樣板時選擇加入。首次流程見 [使用指南](user-guide.md)。

## 保存失敗與重置

一般操作無法寫入時，變更留在目前分頁記憶體，顯示提示並可立即匯出；不顯示為已保存。匯入必須成功寫入才套用，驗證或容量失敗保留原資料。未保存的分頁收到外部更新時，提示先匯出，避免靜默丟棄。

設定提供兩種重置：

| 操作 | 保留內容 |
| --- | --- |
| 清空工作資料 | 外觀、Client ID 與更新設定 |
| 重置整個 Orbit | 回到預設設定 |

兩者均清空工作內容、月曆綁定／快取及本機 Drive 狀態，停止 Google 讀取與自動處理。先提供下載全部備份，要求輸入確認文字並檢查期間是否有其他分頁更新；保存失敗不重置。

成功後移除 Orbit 舊資料與偏好鍵，保留新的空白狀態，避免重新載入舊任務；同來源其他程式的鍵不清除。寫入協調 IndexedDB 維持可用，舊世代未完成的請求不能寫回。Google Calendar 原活動及 Drive 雲端檔案保留。

清除瀏覽器網站資料也會移除本機任務與快取，操作前請先下載備份。

## 文件來源與關聯

第一階段按紀錄保存文件來源與關聯事件，含文件資料的看板為格式 5，完整備份及 Drive 為格式 6。新增／移除事件隨工作空間備份與同步；重建的 metadata 顯示快取獨立保存，不修改工作資料。移除保留事件識別以防止晚到舊資料復活；來源與移除事件尚未回收。所有接續裝置須更新至支援文件格式的版本。操作、並行規則與真實服務界線見 [任務文件連結：第一階段](task-document-phase1.md)。

第二階段新增 `documentDetails`（任務／來源用途及新增事件生命週期）與 `documentOrders`（每個任務的混合來源順序），逐筆存入 IndexedDB。使用新欄位的看板格式 6、JSON 與 Drive 格式 7；舊格式保持歷史校驗，降級包裝新資料會被拒絕。不同用途以共同版本三方整併，同一用途／順序衝突保留候選分支，重新加入不復活已移除事件的用途。[完整規則](task-editor-information.md)。

第三階段的檔案查驗與祖先位置快取只保存在分頁記憶體，任務、側欄與選檔共用結果；按來源、帳號／Client ID、資料世代與權限範圍隔離。查驗更新與快取清理不寫入工作資料、修改時間、復原紀錄或同步摘要，格式維持看板 6、備份 7。清除過期／全部檔案快取保留目前瀏覽位置、任務連結、用途、排序及授權；來源身份與移除事件尚未回收。[檔案資訊更新與清理](document-information-refresh.md)。

第四階段在送出建立要求前，以本機 `iih-orbit-document-operations-v1` 保存操作識別與選項；部分成功保留結果 ID／URL，重新載入可查核，不重送不確定的 POST。建立憑證只在分頁記憶體，最後成功位置使用獨立 `iih-orbit-document-destinations-v1`；兩者均不進任務備份，正常登出清除本機紀錄。關聯必須成功持久保存，且在寫入鎖內驗證任務／來源／世代。安全來源整理只移除全部空間、垃圾桶、衝突、事件、復原／重做、草稿與未完成建立均未引用的孤立來源；本次整理會保存修訂，任務時間不變，歷史標記不壓縮，格式仍為看板 6／備份 7。[建立與清理規則](document-creation-and-cleanup.md)。

## 離線使用

正式版本會在背景準備離線程式，下載完成後可在同一瀏覽器離線重開及編輯本機任務。主畫面不顯示常駐狀態列；更新等待所有分頁關閉，不打斷編輯。[離線使用、更新與驗證範圍](offline-tasks.md)。
