# Orbit 與 Google Calendar 移轉

依已確認的規劃實作。真實 Google 帳號、資料及跨裝置驗收由使用者手動進行，不列為本次實作的未完成工作。

## 使用流程

1. 在「設定 → Google 月曆」連線 Google，選擇要顯示的來源。清單標示可寫入、唯讀或權限待確認。
2. 開啟已保存的 Orbit 任務，按「移至 Google Calendar」。有草稿改動會先保存；沒有改動不產生新的本機保存紀錄。
3. 自動帶入第一個可寫入月曆，可自行改選。首次移轉另授權建立活動；每次送出重新查詢目標月曆的權限。讀取、寫入與 Drive 授權分開保存，憑證不放進備份。
4. 已有完整起訖日期時間時直接沿用，不提供時段選項。缺少開始而有截止日期時才提供三個選項；其他未完成時段直接補齊起訖欄位。Google 活動讀回完整確認且本機結果成功保存，才移除原 Orbit 卡片。目標月曆加入原工作空間的顯示來源。
5. Google 活動明細提供「複製為 Orbit 任務」。先載入最新內容，再預覽名稱、描述、時段、子任務及本機分類。確認時再檢查這筆 Google 活動是否在預覽後更新，每次確認都建立獨立的新任務。Google 活動保留。

複製後兩邊各自存在；Orbit 副本再次移轉會建立新的 Google 活動。

## 月曆清單快取

設定、側欄與移轉面板共用同一份月曆清單，保存月曆名稱、顏色、時區與權限角色。快取依資料世代、Client ID 與帳號隔離，效期五分鐘；開啟移轉面板或重新連線時先顯示快取，過期才自動讀取。重新整理頁面後也能沿用，相同帳號的並行讀取共用一次請求。

「更新月曆清單」可手動強制更新；更新失敗仍保留清單並顯示原因。送出活動前一律重新檢查目標月曆權限，因此快取中的寫入角色不能繞過已撤銷的權限。帳號或資料世代改變後，舊回覆不會寫入新清單。快取只包含月曆資訊，不保存憑證或活動內容。

## 在 Google Calendar 開啟活動

使用 Google API 回傳的 `htmlLink`，保留活動識別資訊及時區。開啟時移除網址中可能固定的 `/u/0` 等登入序號，改以 Orbit 已連線帳號的電子郵件設定 `authuser`；再經 `accounts.google.com/AccountChooser` 帶入 `Email` 與 `continue`。使用帳號電子郵件，不把月曆 ID、擁有者或瀏覽器登入順序當成目標帳號。

活動明細顯示預期開啟的帳號；缺少帳號資訊或來源屬於其他帳號時不提供原始連結，要求重新連線。這些網址參數用於提示 Google 選擇帳號，不能替代 Google 網站的登入驗證；未登入時可能先進入登入或帳號選擇。也不傳遞 OAuth token、不修改來源活動連結或保存資料。

Google 的公開 Calendar API 文件只將 `htmlLink` 定義為網頁活動連結，沒有保證浮動彈窗的網址介面。實作保留該活動連結，不自行猜測 Google 內部的彈窗路由；最後顯示為彈窗或活動明細頁由 Google 決定，真實多帳號操作由使用者驗收。

## 時段

| 選項 | 行為 |
| --- | --- |
| 截止前預留時間 | 15 分鐘、30 分鐘、1 小時或 2 小時；結束等於原截止點，開始向前推算，可跨午夜。缺少截止日期或時間須補齊。 |
| 當天全天截止提醒 | 依原截止日期建立全天活動；Google 結束日期為隔天，不多顯示一天。 |
| 自行安排時段 | 使用者選擇起訖日期時間；日期截止但缺少結束時間時須補齊。 |

截止日期與時間並排，預留長度獨立一列。完整時段只顯示起訖預覽；沒有截止的任務直接補齊日期時間，只有開始的任務預填一小時供確認。活動全部設定為有空，不提供忙碌選項。預覽顯示本機時區。不存在的夏令時間、無效日期與結束不晚於開始均不可送出；原有 Orbit 時程不因預覽改動。

## Google 描述與子任務

活動名稱採任務名稱，描述前段保留原描述，後段使用固定標記，例如：

```text
準備期末報告。

--- IIH Orbit 任務 v1 ---
專案：課程
分類：研究規劃
狀態：進行中
優先順序：高優先
子任務：
[x] 閱讀文獻
[ ] 整理資料
--- IIH Orbit 任務結束 ---
```

子任務順序、名稱與完成狀態可解析回 Orbit。含換行或以引號開頭的名稱使用 JSON 字串轉義，避免破壞格式。標記被刪除、格式不完整或未知格式時不猜測子任務，保留整段原描述供使用者處理。移轉前檢查內容長度，避免截斷後刪除本機資料。這是文字清單，不建立 Google Tasks。

一般 Google 活動的 HTML 描述轉為可讀文字。超過完整處理範圍的活動標示為節錄，不能複製，移轉讀回也不接受截斷內容。

未完成移轉的重試紀錄隨工作空間、檔案與 Drive 備份保留；匯入副本改寫 Orbit 識別碼，保留待確認的 Google 活動 ID 與原快照。移轉完成後移除該紀錄。新副本不保存 Google 來源識別碼。既有備份的舊來源欄位僅保留讀寫相容，以免改變 Drive 校驗值；不參與顯示、編輯或配對。

## 獨立複製與顯示

Google 活動與複製出的 Orbit 任務在月／週視圖及提醒中各自呈現。即使內容完全相同，也不合併、不隱藏；重新整理後維持相同行為。Orbit 任務可編輯，Google 活動維持唯讀並可開啟 Google 查看。

每次複製都有新的任務及子任務 ID；不尋找已有副本、不覆寫既有任務，也不保存同源關係或進行逐筆內容比較。兩邊後續修改互不更新。可用顯示來源開關單獨查看 Google 或 Orbit。

## 中斷與競爭

先成功保存待確認的活動 ID、原任務快照與送出內容，再呼叫 Google。重試沿用同一活動 ID，先查詢既有活動；409 也讀回同一活動，沒有 Google 更新或刪除呼叫。移轉作業使用跨分頁鎖及租約，資料世代、帳號、授權、頁面離開與保存交易內都再次檢查。

網路失敗或保存失敗保留原任務與移轉紀錄。另一分頁編輯任務時只確認 Google 結果，新版 Orbit 任務保留。Google 活動在斷線後已被修改，且移轉標記仍可確認時，結束原移轉、保留兩邊並提示自行查看。移轉標記不明時不覆寫、不另建活動，保留 Orbit 供重新確認。這個標記僅用於中斷重試；不連結複製回來的任務。未確認紀錄的預覽展示原送出內容，不把新草稿誤當成已送出的內容。

從移轉返回任務保留原編輯基準；另一分頁已修改或刪除時顯示衝突處理，不會把舊草稿當成最新內容覆寫，也不會自動復活已刪除任務。

## 依據

- [Google 活動網頁連結](https://developers.google.com/workspace/calendar/api/v3/reference/events#resource)：`htmlLink` 指向該活動的 Google Calendar 網頁介面。
- [Google Site Kit 多帳號連結處理](https://github.com/google/site-kit-wp/issues/1456)：以使用者電子郵件指定 `authuser`，避免依賴無法從 API 得知的瀏覽器登入序號；這不是 Calendar 彈窗的公開介面保證。
- [Google Calendar 月曆權限](https://developers.google.com/workspace/calendar/api/v3/reference/calendarList)：writerWithoutPrivateAccess、writer、owner 可寫入；未知角色不開放移轉。
- [建立活動與自訂活動 ID](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert)。
- [Google OAuth 授權範圍](https://developers.google.com/workspace/calendar/api/auth)與[逐項檢查授權](https://developers.google.com/identity/oauth2/web/reference/js-reference#google.accounts.oauth2.hasGrantedAllScopes)。
