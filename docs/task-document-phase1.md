## 操作方式

- 到「設定 → Google Drive」連線唯讀檔案瀏覽，或在「Google 連線」保存 Client ID 後使用「一次授權全部服務」。右側欄的「檔案」分頁可查看「我的雲端硬碟」與「與我共用」，不另顯示服務名稱與帳號；齒輪可直接開啟 Google Drive 設定，管理帳號、重新授權、解除連線。
- 側欄分頁只有目前選取項目顯示圖示與名稱，其他只顯示圖示，仍提供名稱與鍵盤 tooltip。
- 每次只列出目前資料夾的直接子項目，排除備份使用的「IIH Orbit」資料夾；點資料夾名稱，或雙擊資料夾圖示／列上的空白處進入，以返回上層或麵包屑導航。搜尋只查目前位置的檔名。每頁 100 筆，以「載入更多檔案」取下一頁；畫面最多保留 1000 筆，較多時提示縮小搜尋。
- 側欄、選檔視窗及已保存連結使用相同檔案圖示。依 [Google 檔案類型](https://developers.google.com/workspace/drive/api/guides/mime-types) 顯示文件、試算表與簡報圖示；Colab／`.ipynb`、PDF、圖片及 `.ecmx` 也有對應造型。ECMX 以使用者附圖的灰色圓形與游標重繪 SVG，支援深淺主題。判斷只用既有 metadata、已知 Google 網址或副檔名，不讀取內文；捷徑優先使用目標類型。
- 檔案與資料夾都可拖曳。看板卡片中央顯示「放開以加入資訊連結」；上下緣、間隙或空欄顯示新增任務 placeholder。放開直接保存任務與來源關聯，插入指定卡片前，沿用欄位狀態及目前專案，不再開啟新任務草稿。
- 清單任務列中央加入連結，列邊緣或空白處建立新任務。月視圖空白日期、週視圖全天區建立同日全天任務；週時間欄每 15 分鐘對齊，建立一小時的任務，跨午夜時截止日期順延。
- 月／週視圖內的 Orbit 任務直接接收連結，不新增任務或改動其時程。Google Calendar 活動不可連結，拖曳時顯示不可放置，不會冒泡成日期上的新任務。
- 列表的＋開啟帶來源的任務草稿，可修改或取消。任務表單改稱「資訊連結」，按「瀏覽 Drive 加入連結」開啟獨立視窗，可選取或取消選取多份檔案／資料夾，確認後才更新草稿。取消、Escape 或遮罩只取消選檔，任務表單及原草稿保留；另保留「貼上 Drive 連結」。草稿的新增／移除只在儲存任務後生效。
- 選檔視窗與側欄同樣顯示相關任務數量，展開後只列出已保存關聯的任務名稱，沒有跳轉連結；側欄仍保留開啟相關任務的按鈕。未確認的選取不改變相關任務數量。
- 看板卡片與清單名稱欄在有有效關聯時顯示「資訊連結 N 項」，包含檔案、資料夾與 Gmail。相同來源不重複計數，移除／復原與工作空間切換更新數量，無連結時隱藏提示。計數依工作空間快取，不逐張卡片重掃來源與事件。
- 資料夾名稱只進入下一層，檔案名稱為文字；緊接檔名／資料夾名稱的 ↗ 才在新分頁開啟原項目。任務已保存的資訊名稱仍可開啟原來源。同一來源可關聯多個任務，列表提供跨工作空間的相關任務入口；垃圾桶任務不列入目前相關任務。
- Gmail 郵件採相同落點規則：中央加入資訊連結且保留既有任務內容與時程，邊緣／空隙或月／週空白落點建立已連結的新任務。Google 活動阻擋。郵件的建立任務按鈕與預覽建立也帶入資訊連結；重複加入不重複呈現，移除只解除 Orbit 關聯。
- 檔案瀏覽只提供 Google Drive API 回覆的項目；尚未連線時顯示前往設定的提示。程式內的範例檔案與示範模式已移除；先前保存的範例關聯仍可顯示名稱及移除，不開啟虛構網址。

檔案瀏覽列表本身不建立、改名、移動、下載或刪除雲端原檔；任務中的「建立文件」使用另行授權的獨立流程。文件內容與 OAuth 憑證不進來源資料或備份。郵件資訊連結只保存主旨、寄件人、帳號／郵件識別與開啟 URL；既有「郵件建立任務」流程仍帶入預覽描述，但加入既有任務不複製郵件內容。

## 資料與來源身份

每個工作空間分開保存 `documentSources` 與 `documentLinks`；相同來源識別可跨工作空間反查，不使用暫時登入序號作為來源身份。IndexedDB 為文件來源與每個關聯事件各保存一筆紀錄，不把文件陣列嵌入每個任務。

來源只保存服務、來源範圍、穩定檔案識別或已確認的完整定位、開啟連結，以及初次加入時的名稱／位置／類型快照。來源讀取採欄位白名單，不保存外部文件內容或登入憑證；含標準 OAuth token／secret 參數的開啟連結被拒絕。

有服務端識別時，以「服務＋來源範圍＋識別碼」形成固定 Orbit 來源識別。Google 文件／試算表／簡報及 Drive 檔案的常見連結可取出穩定檔案 ID，以共同 Drive 識別範圍辨識，不依觀看帳號區分同一檔案。pCloud／Microsoft 365 的服務介面可透過 `createDocumentSource` 提供來源範圍及穩定 ID。

Gmail 以帳號與單封郵件 ID 辨識來源，討論串中的回覆分開保存，沿用目前 Gmail 的帳號導向原信連結。URL 只允許 Gmail 開啟網址或導向該 Gmail 網址的 AccountChooser，不接受任意轉址。郵件來源沿用同一套關聯、移除事件、IndexedDB 及格式 6 備份／整併。

缺少穩定 ID 時，只有服務介面能確認完整定位才使用路徑備援；手動分享連結保留待辨識身份，不按檔名或文件內容強行合併。同一裝置重複貼上已登錄的完全相同連結會重用其來源；不同連結指向同一檔案但尚無可靠身份時，仍可能出現兩份待辨識來源，留待服務串接確認。

## 新增、移除與同步

每次新增關聯保存獨立事件識別，連到任務與來源。相同任務／來源在畫面及查詢只呈現一次；兩台裝置並行新增時可保留兩個事件，但不重複顯示文件。移除會標記所有已觀察到的有效事件，不抹除事件識別。

整併不比較裝置時間。同一事件的移除標記勝過舊有效副本，晚到版本不能復活該事件；再次加入另建新事件。移除與另一台裝置新建一個獨立事件並行時，保留那個新事件。這是本階段採用的關聯衝突規則。

文件資訊不參與任務內容版本的選擇；多份來源顯示快照不同時按固定排序選取，不借用裝置時間決定任務內容。不同文件的新增可以自動保留；任務描述衝突仍使用既有待選版本流程。

復原／重做文件操作保留舊刪除記錄，重新加入使用新事件。任務移到垃圾桶時保留關聯；單筆徹底刪除會移除該任務的有效關聯，清空後也會將不再有任務或待選紀錄參照的有效事件標記移除。歷史事件保留，尚未壓縮；完全無引用的孤立來源可由後續加入的[安全整理](document-creation-and-cleanup.md#無使用來源整理)移除。

## 備份與相容性

含文件資料的工作空間使用看板格式 5，本機完整 JSON 與 Drive 版本使用格式 6。未使用文件的舊資料仍保持原有格式，歷史備份仍可讀取。

自動同步沿用分塊與父版本整併，文件資料在工作空間 metadata 區塊中；格式 6 的區塊也受歷史與回收引用保護。手動 JSON 匯出與手動 Drive 獨立備份仍是可獨立還原的完整 JSON。選定工作空間匯出包括該空間的來源、關聯及保留的刪除事件。

加入工作空間副本會重新編號工作空間、任務及關聯事件，來源身份與開啟連結仍指向原檔。全部還原維持資料世代檢查，舊分頁不能把還原前的關聯寫回。

所有裝置均須更新到支援格式 6 的 Orbit 才能接續含文件的同步集合。舊版對看板格式 5 或 `v6:` 雲端版本的讀取會失敗，避免漏掉新欄位後寫回。新程式也拒絕用舊備份／Drive 格式包裝文件資料。

儲存失敗沿用任務操作語意：磁碟交易整份中止，完整變更可暫留目前分頁並顯示未保存提示，仍可匯出備份並在儲存恢復後重試。全部還原等要求實際保存的操作失敗時，原磁碟資料及畫面資料保留。

## Metadata 快取與授權

檔案列表快取只留記憶體，每個查詢五分鐘、最多八個資料夾／搜尋結果。一般重開與返回位置使用快取，明確重新整理重新請求。導航新請求、資料世代、Client ID 或帳號變更會取消舊請求，晚到結果不能覆蓋目前列表。載入失敗保留上一次成功的列表與路徑。檔案拖曳使用同分頁的短期 token，放置前再次驗證來源、帳號與工作空間。

側欄與選檔視窗共用 `DriveBrowserConnection` 的授權與帳號，每個視窗各自提供 `DriveBrowser`，獨立保存路徑、搜尋、列表快取與未確認選取。選檔視窗按需載入，關閉只中止自己的請求；側欄位置與其他請求保留。帳號、Client ID 或資料世代變更時各自取消舊瀏覽，未確認選取也重設。

`DocumentMetadataCache` 只更新可重建的顯示名稱與瀏覽位置，不修改工作空間、任務編輯時間或同步雜湊；按資料世代及瀏覽帳號隔離。尚未再次瀏覽的來源使用已保存的快照，不宣稱已查驗目前權限或原檔狀態。

瀏覽採 `drive.metadata.readonly`，可個別連線或加入全部服務授權；其憑證與連線狀態獨立保存，包含在全部已連線與到期提示的判斷中。既有 `drive.file` 備份授權與清理範圍保留。解除瀏覽連線不移除任務連結；整體登出會清除瀏覽憑證。

列表查詢先依備份資料夾的私有 `orbit=v1`／`type=folder` 標記及預設名稱排除，再於回應處理時以標記及忽略大小寫的名稱作防護。改名的已標記備份資料夾、舊同名資料夾及同名資料夾捷徑皆不顯示；一般檔案不因同名而排除。隱藏項目不丟棄下一頁游標，私有屬性不進任務來源快照。只改變瀏覽結果，備份保存與清理流程照常運作。查詢語法依 [Google 官方文件](https://developers.google.com/workspace/drive/api/guides/search-files)。

API 使用 [Drive files.list](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/list) 的 parents 查詢、欄位篩選、分頁及共用硬碟參數，支援資料夾捷徑與 resource keys。該 scope 屬於 Google restricted scopes，正式對外授權需依 [Google 官方驗證要求](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) 配置 OAuth 應用程式。

2026-10-14：修正可選開啟連結造成整份資料夾載入失敗的問題。API 回傳的 [`webViewLink`](https://developers.google.com/workspace/drive/api/reference/rest/v3/files) 用來開啟相應 Google 編輯器／檢視器；若網址不符合 Orbit 的安全連結規則、空白或損壞，改用已驗證的檔案識別與 resource key 產生 Drive 備用連結。項目及穩定來源身份保留，未接受的原網址與其參數不進任務或備份；必要 metadata 的完整性驗證仍保留。
